# fServe: техническое задание (состояние на v1.6.2, основа для v2)

Документ написан по итогам разработки версий 1.x. Его цель: с него можно начать новый чат для версии 2, не перечитывая старую переписку. Подробности: [README.md](README.md) (функции), [script.md](script.md) (язык сценариев, источник истины по DSL), [CLAUDE.md](CLAUDE.md) (правила работы).

## 1. Назначение и пользователи

Android-приложение `com.ffps.fserv` («fServe») для комнаты пожилого человека: киоск, голосовой помощник, задачи по расписанию и по голосу, наблюдение за движением по фронтальной камере, сообщения близким в Telegram, видеозвонок.

- Пользователь-человек: пожилой, ничего не настраивает; общается голосом и касанием экрана.
- Администратор (близкий): настраивает всё из браузера (в т.ч. удалённо), пишет задачи текстом.
- Это помощник, а не система безопасности.
- Статус: 1.x «в целом готово», опытная эксплуатация. v2 открывается только под новые задачи.

## 2. Устройства и ограничения

| Устройство | Роль | Особенности |
|---|---|---|
| Galaxy A3 (2017), Android 8 | целевое, медленное | распознавание речи идёт со скоростью ×0.3–0.9 реального времени; всё должно работать экономно |
| Tab A7 Lite SM-T225, Android 14 | целевое, в другом доме | у админа есть доступ до устройства; нужен foreground-тип службы для камеры/микрофона |
| Galaxy S23 | только для разработки | не целевое, для тестов на "мощном" устройстве |

Требования: minSdk 26, без использование Google-сервисов в критичных местах, постоянная зарядка, Wi-Fi, приложение — домашний экран (HOME). Device Owner не реализован.

## 3. Архитектура

Один процесс, foreground-служба (`ServerService`) держит всё:

- **Киоск**: `MainActivity` с WebView; страница `kiosk.html` (часы, дата, погода, кнопка звонка); заменяется файлом в `web/`. Не возвращается на передний план сам (только автозапуск, обновление, мягкий перезапуск, входящий звонок); есть `POST /api/kiosk/show` и шаг `kiosk show`.
- **Веб-сервер** (`WebServer`, HTTP 8080 + HTTPS 8443 с самоподписанным сертификатом `https.p12`): админка `assets/index.html` (SPA), `/health` без входа, `/api/*` с авторизацией (cookie-сессия 1 год или Basic `admin:пароль`), `/phone` и `/#call` для звонка.
- **Планировщик и движок задач**: `Scheduler`, `Cron`, `TaskStore/TaskSet`, `Script` (разбор), `TaskSchema` (проверка), `TaskEngine` (выполнение), `Expr`, `Dur`, `Lists`.
- **Голос**: `Voice` (TTS, Google TTS), `Stt`/`Speech`/`LevelGate`/`VoiceTrigger`/`VoiceCmd`/`TailPick` (Vosk), `Sounds`, `Audio`.
- **Датчики**: `CameraEngine` (Camera2, движение), `CameraTest`, `PhotoStore`.
- **Связь**: `Telegram` (очередь), `Net`/`Https` (HTTP, SOCKS5), `Llm`/`Chat`, `Weather`/`WeatherText`, `Call` (WebRTC).
- **Обслуживание**: `Updater`/`UpdateReceiver`, `Backup`, `Starter`, `FLog`, `Load`/`ProcStat`, `Power`, `BootReceiver`.
- **Настройки**: `Settings` (JSON), нативное окно `SettingsActivity` только для порта, пароля, автозапуска, кнопки службы.

## 4. Язык сценариев (кратко; полно в script.md)

Варианты языка сценариев на основе json, python, lua были рассмотрены и отброшены в пользу собственного синтаксиса.

Задача — файл `tasks/<id>.txt`, текст с отступами. Заголовок: `task` с параметрами `cron`, `voice="фраза|фраза"`, `preempt` (0–9, у `call` по умолчанию 9). Специальные задачи `call` и `ring`.

Шаги: `say`, `ask` (kind=yesno/number/text), `chat` (диалог с LLM: `for`, `turns`, `assign`, `alert`, `from=user`, `ok`), `play`, `slide`, `photo`, `stop_background`, `background`, `telegram`, `request` (HTTP), `kiosk show`, `delay`, `watch` (ждать движение), `if`, `repeat`, `stop`, `log`. Подстановки `{имя}`, условия, общие списки `lists.txt` (`@имя`), пробный запуск (dry-run с `assume`).

Правила изменения языка: любое изменение сразу отражать в `script.md` (с номером версии в шапке) в том же коммите; блоки `task` верхнего уровня в script.md должны проходить разбор (`ScriptTest.examplesInDocsAreValid`).

### Запуск голосом
- Слушатель: часы (`listen.hours`, пусто = выключен), префикс-имя (`Кузя` по умолчанию, можно несколько через `|`), порог громкости (`level`, 0–50 %).
- Первый проход: грамматика Vosk из фраз задач; `*` в конце фразы — свободный хвост, который распознаётся вторым проходом (`TailDecoder`), `{phrase}` — сказанное целиком.
- Параметры: чанк 0.1 с, `END_SILENCE=10` чанков, `NO_SPEECH_SEC=3.0`, `MIN_TAIL_WORDS=2`; `listen.tail` 2..15 с (по умолчанию 8) с мягким продлением (`SOFT_PAUSE=3`, `SOFT_EXTRA_SEC=3.0`); после хвоста звук-отклик (`ack`), при неразборе фраза `miss`.
- Слушатель уступает микрофон `ask`/`chat`/звонку и молчит, пока говорит синтезатор.
- Значения по умолчанию без блока `listen`: hours "", prefix "Кузя", level 1, tail 8, ack "sys.mp3", miss «Я не расслышал вас, повторите пожалуйста!».

### Шаг request
GET по умолчанию, POST при `post=`; `method`, `type`, `header` (строка или список), `proxy=true` (профиль `request_proxy`), `timeout` 1..60 с (по умолчанию 5), `assign` (успех = любой 2xx), `body` (≤4 КБ текста ответа), `code`; список адресов выполняется весь по порядку (≤50). Подстановки в URL кодируются, в JSON-теле экранируются. Логин/пароль в URL → Basic, в логе маскируются `***`, запрос скрыт. Пробный запуск ничего не отправляет. В лог пишется ответ до 4096 символов. Разрешён http (cleartext включён в манифесте).

## 5. Подсистемы и принятые решения

**Речь (TTS).** Только системный движок Google TTS. `say` с 20-секундным таймаутом старта, при сбое движок пересоздаётся; сбой `say` не фатален (одно уведомление в Telegram за запуск). Автоматический переход на другой движок не нужен (решение пользователя). Прогрев синтезатора раз в несколько минут при наличии задач с речью. Язык и голос выбираются двумя селекторами в админке (список из `/api/voice?lang=`; ручной ввод не нужен: если список не получен, вводить нечего). Язык нормализуется `_`→`-`.

**Распознавание (STT).** Vosk, малая русская модель (~45 МБ, скачивается из админки). Порог громкости не отдаёт распознавателю тишину (экономит CPU на A3). Раз в 10 минут в лог (тег `load`) пишется нагрузка.

**LLM.** Любой OpenAI-совместимый API (пресеты Groq, Gemini, «Другой»), отдельные адрес/ключ/модель на пресет, прокси «LLM». Ответ модели — объект {реплика, тревога, конец}. Общие правила на вкладке «Чат» (пусто = `Chat.DEFAULT_RULES`: 7 строк, без даты/времени/погоды, если не спросили). Вкладка «Чат» показывает свёрнутый блок «Что ушло модели».

**Камера.** Camera2, 640×480 ~10 к/с, сетка 64×48, сравнение яркости без средней; зоны, график, стресс-тест. Foreground-тип camera.

**Звонок.** WebRTC точка-точка в LAN, по https :8443, без подтверждения на устройстве; камера и микрофон на время звонка принадлежат звонку; кнопка колокольчика запускает задачу `ring`.

**Telegram и сеть.** Очередь ≤200 сообщений, срок 24 ч, при HTTP 400 ≤3 попыток; SOCKS5 с авторизацией, профили для Telegram, LLM, погоды, обновлений, `request`.

**Погода.** Open-Meteo без ключа, строка на киоске, в подсказку чата.

**Обновление.** Проверка и установка из GitHub Releases; ручная загрузка APK кнопкой «Загрузить» (`POST /api/update/upload`: тот же пакет, подпись, versionCode новее, нужен `canInstall`). Загрузка с GitHub иногда даёт 504 (на стороне GitHub), для этого и сделана ручная загрузка.

**Резервная копия.** zip: `settings.json`, `tasks/`, `lists.txt`, `sounds/`, `slides/`, `pages/`. Не входят: модель Vosk, разрешения Android, данные TTS, история/лог/фото. После восстановления на другом устройстве перепроверить: имя голоса, `listen.level` и `tail`, поворот/зоны/разрешение камеры, разрешения звонка, пароль/порты, прокси и адреса LAN.

**Стартовый набор.** `assets/starter.zip` (задачи, `lists.txt`, слайды, звуки; без `settings.json`) ставится один раз на чистой первой установке (маркер `starter.done`: свежая установка = `lastUpdateTime − firstInstallTime < 60 с` и пустые данные); при сбросе админка спрашивает, ставить ли набор. Имя маскота по умолчанию «Кузя», формы речи — мужской род.

## 6. Сборка, релиз, тесты, процесс

- Приложение собирает **только CI** (GitHub Actions), APK подписывается постоянным ключом из секретов репозитория. Релиз: маркер `[release vX.Y.Z]` в последнем коммите на `main`; в Releases: `fServe-X.Y.Z.apk`, `.sha256`, `version.json`. `versionCode = major*1000000 + minor*1000 + patch`.
- Android-зависимый код компилируется только в CI; чистые файлы (Script, TaskSchema, Expr, Dur, Cron, TailPick, Starter-проверка…) тестируются локально kotlinc + JUnit (99 тестов); JS админки — `node --check`.
- Контроль CI: `gh run list --repo ffps/fserv --limit 1 --json status,conclusion,headSha`; релиз: `gh api repos/ffps/fserv/releases/tags/vX`.
- Рабочий процесс пользователя: тестирует, собирает замечания, часто говорит «пока ничего не правь» до команды «делай». Серьёзные возражения высказывать до действий. Общение по-русски. Коммиты оканчиваются строками Co-Authored-By и Claude-Session.

## 7. Известные особенности и уроки

- A3 медленный: распознавание ×0.3–0.9; «хвост» задан 8 с с мягким продлением, диагностика «слушали до: …» пишется в лог.
- Привязка по времени, когда звук идёт раньше имени, иногда сбивается (диагностика в логах).
- Google TTS после обновления на A7 мог отдавать пустой список голосов или ошибку «нет голоса ru-RU»; помогла переустановка/состояние движка, причина не подтверждена.
- Android 14: микрофонная foreground-служба после обновления может требовать повторного старта.
- После обновления админки браузер может держать старую страницу — Ctrl+F5.
- Исходники слоёв иконки (SVG) в репозитории отсутствуют.
- Ответ `request` в DEBUG-логе — полностью до 4096 символов (в логе дублируются строки шагов).

## 8. Идеи для v2 (не заказаны, к обсуждению)

1. Настройка автовозврата киоска на передний план (сейчас только `kiosk show`).
2. Необязательная настройка `voice.engine` (без автоматического запасного движка).
3. Хранить исходники иконки в репозитории.
4. Новые шаги и интеграции для домашней автоматики на основе `request` (по мере появления задач).

## 9. С чего начинать новый чат

1. Прочитать этот файл, `CLAUDE.md`, затем `README.md` и `script.md` (разделы по задаче).
2. Склонировать `https://github.com/ffps/fserv`, ветка `main`; проверить, что CI зелёный и последний релиз совпадает с версией в шапке `script.md`.
3. Не менять код до явного «делай»; сначала обсудить правки и возражения.
4. Любое изменение языка: `Script.kt` + `TaskSchema.kt` + `TaskEngine.kt` + тесты + `script.md` (версия в шапке) в одном коммите; релиз маркером в коммите.
