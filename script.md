# Язык сценариев fServe

Задачи описываются коротким текстом. Каждая задача хранится в своём файле `tasks/<id>.txt` на устройстве: `id` задаётся отдельным полем в редакторе и служит именем файла, в самом тексте его нет. Голос и зоны детектора движения в сценариях не описываются: это настройки приложения (вкладки «Звук» и «Камера»). Задачи редактируются в веб-интерфейсе (вкладка «Задачи»), каждая отдельным редактором. Любое сохранение проходит проверку: опечатка в имени параметра или действия считается ошибкой, чтобы задача не работала молча не так, как задумано. Сообщение об ошибке называет строку («строка 7: у play нет параметра «fade»; допустимы: …»), и её номер совпадает с номером слева от текста в редакторе. Перед каждым сохранением набор файлов целиком попадает в историю (последние 3 версии). Ошибка в одном файле отключает только свою задачу: остальные работают, а в списке задач она помечена ошибкой.

> Этот файл описывает версию приложения 1.4.8 и обновляется вместе с каждым изменением языка (см. [`CLAUDE.md`](CLAUDE.md)). Если описание и поведение разошлись, считайте ошибкой описание и сообщите об этом.

## Пример

```
# Будильник: сигнал нарастает, пока на кровати нет движения
task "Подъём" cron="0 8 * * *" timeout=60m

  repeat 10 until=moved
    watch 30s poll=600ms assign=moved
    if not moved
      background
        play system:alarm volume=80 fade_in=5s
        delay 10s
        say "Просыпайся! Пора вставать."
  if moved
    say "Доброе утро!"
    photo assign=photo1
    telegram "Встал в <b>{time}</b>" files=[photo1]
  else
    telegram "К {time} не встал"
```

## Как пишется текст

- **Отступ** задаёт вложенность: ровно 2 пробела на уровень, только пробелы (табуляция — ошибка). Шаги внутри `repeat`, `if`, `else`, `background` пишутся на строках ниже, с отступом на 2 пробела больше.
- **Строка** — одно действие: слово действия, затем первый аргумент без имени (если он нужен), затем параметры `ключ=значение`, затем флаги. Флаг — это параметр-«да»: `loop` означает то же, что `loop=true`.
- **Комментарий** начинается с `#` и идёт до конца строки; строка из одного комментария допустима где угодно. Внутри текста в кавычках `#` — обычный знак.
- **Пустые строки** игнорируются.
- **Значения:**

| Запись | Значение |
|---|---|
| `70`, `0.95` | число |
| `true`, `false` | логическое значение |
| `30s`, `system:alarm`, `alarm.mp3` | слово без пробелов, строка |
| `"Доброе утро!"` | текст в кавычках; внутри допустимы `\"`, `\\`, `\n` (перевод строки), `\t` |
| `[a,b,c]`, `[3s, 5s, 10s]` | список (запятые, пробелы после запятых допустимы) |

Текст в `say`, `telegram`, `log`, `stop` и название задачи пишутся **только** в кавычках. Остальные значения в кавычки брать не нужно, если в них нет пробелов (`cron` содержит пробелы, поэтому его пишут в кавычках).

## Файлы задач

- Файл задачи (`tasks/<id>.txt`) начинается строкой `task` (перед ней допустимы комментарии и пустые строки), дальше идут настройки и шаги. Одна задача на файл. Голос и зоны детектора движения в файле задачи не описываются: это настройки приложения.
- `id` задачи: латинские буквы, цифры, `_`, `-`, до 40 знаков, начинается с буквы или цифры (не с `_`). Он служит именем файла, подставляется в имя фото (`ЧЧММСС.id.jpg`) и в журнал; если у задачи нет названия, вместо него показывается `id`. Переименование задачи в редакторе переименовывает её файл.
- Задачи в списке идут по `id`.

## Голос и зоны (настройки приложения)

Хранятся в `settings.json` (входят в резервную копию) и задаются в веб-интерфейсе, а не в тексте задач.

### Голос (вкладка «Звук», «Общие настройки»)

| Параметр | Значения | Описание |
|---|---|---|
| Громкость по умолчанию | 0..100 | Громкость для `say`, `ask` и `play`, если у шага нет своего `volume`. Это громкость системного потока «медиа» устройства. |
| Язык голоса | `ru-RU`, `en-US`… | Язык синтезатора речи. |
| Голос | имя голоса | Конкретный голос системного синтезатора. Пусто = голос по умолчанию. В списке на вкладке «Звук» у каждого голоса указаны источник (автономный или нужен интернет), качество и задержка, а кнопка ▶ проверяет голос. |
| Скорость речи, % | 30..300 (целое) | 100 = обычная; не задана = 100. |
| Тон голоса, % | 30..200 (целое) | 100 = обычный; не задан = 100. |

Говорит системный синтезатор речи Android; какой именно (Google, RHVoice и другие) — выбирается в настройках устройства («Синтез речи»).

### Зоны детектора движения (вкладка «Камера»)

Зона ограничивает область кадра для детектора движения. Её рисуют мышью поверх кадра с камеры: один или несколько прямоугольников (учитываются все) и вырезы (исключаются из зоны). Координаты хранятся в долях кадра от 0 до 1: `[x1,y1,x2,y2]`, где `x1 < x2`, `y1 < y2`, точка (0, 0) — левый верхний угол. Имя зоны: латинские буквы, цифры, `_`. Зона подключается в `watch` параметром `zone=bed`; если зону удалить, задачи, которые на неё ссылаются, получат ошибку.

## Задачи call и ring

Два id задач имеют особый смысл (остальное в них обычное: любые шаги, `enabled=false` выключает):

- **`call`**: если такая задача есть и включена, на экране киоска внизу по центру появляется круглая кнопка звонка. Нажатие запускает задачу; у `call` по умолчанию `preempt=9` (высший приоритет), поэтому она срабатывает сразу, прервав то, что выполнялось, в том числе задачу с `preempt=true` (отключить: `preempt=false`). Пока она выполняется или ждёт очереди, нажатия игнорируются, а при видеозвонке кнопка скрыта. Обычно в ней голосом просят подождать и отправляют сообщение в Telegram. Сам видеозвонок делается из веб-интерфейса, вкладка «Звонок».
- **`ring`**: запускается кнопкой-колокольчиком на вкладке «Звонок» (она доступна только во время звонка): сигнал, если собеседник отошёл или не слышит.

```
task "Звонок"
  telegram "Вызов с устройства в {time}" confirm=10s assign=sent
  if sent
    say "Я сообщил! Подожди немного, сейчас тебе позвонят."
  else
    say "Сообщение пока не отправилось. Если срочно, позвони по обычному телефону."
```

```
task "Сигнал"
  play system:alarm volume=70 for=5s
```

## Задача

Настройки можно писать в строке `task` или на строках ниже, с отступом (до первого шага), или сочетать оба способа. Один и тот же ключ дважды — ошибка.

```
task "Подъём" cron="0 9 * * *" timeout=60m

  say "Доброе утро!"
```

```
task title="Подъём"
  cron="0 9 * * *"
  late_ok=0
  timeout=60m
  enabled=true

  say "Доброе утро!"
```

Заголовок: слово `task` и необязательное название: в кавычках сразу после `task` или как `title="…"`; `id` в заголовке не пишется (см. выше). Длинные настройки удобнее писать ниже: каждую можно закомментировать или подписать.

| Настройка | По умолчанию | Описание |
|---|---|---|
| название (`"…"` после `task` или `title=`) | = `id` | Название для людей: список задач, журнал, подстановка `{task}`. |
| `enabled` | `true` | `enabled=false` выключает запуск по расписанию и голосом. Вручную выключенную задачу запустить можно. |
| `cron` | — | Расписание (см. ниже), пишется в кавычках. Без `cron` задача запускается только вручную. |
| `voice` | — | Фразы запуска голосом, в кавычках через `\|`: `voice="поболтай со мной\|ты здесь"`; поддерживает шаблоны `(а\|б)`, `[а\|б]`, префикс-имя помощника и фразы `=…` без префикса. Подробности в разделе [Запуск голосом](#запуск-голосом). Можно вместе с `cron`. |
| `late_ok` | `0` | Насколько опоздавший запуск ещё разрешён (длительность). Запуск по расписанию, который не успели начать (устройство было выключено, очередь была занята), выполняется, если опоздание не больше `late_ok` плюс запас в 60 секунд на очередь. Иначе запуск пропускается и это записывается в журнал. По умолчанию опоздавшие запуски всегда пропускаются. Верхний предел окна поиска пропущенного срабатывания — 12 часов. |
| `timeout` | `60m` | Максимальная длительность всей задачи. Если не уложилась, задача останавливается со статусом `timeout`. |
| `preempt` | `false` (у задачи `call` — `9`) | Приоритет: `false` — обычная задача (0), `true` — 1, число от 0 до 9 — свой уровень. Задача с приоритетом выше нуля **встаёт в очереди перед задачами с меньшим приоритетом и прерывает выполняющуюся, если у той приоритет меньше** (та получает статус `cancelled`, причина «прервана задачей…», и не возобновляется). Задачи с **равным** приоритетом друг друга не прерывают: следующая ждёт очереди (поэтому две голосовые задачи не будут бесконечно прерывать друг друга). Так задача `call` (9) прерывает любую, а `Собеседник` с `preempt=true` — только обычные; хотите, чтобы, например, напоминание о таблетках прерывало и разговор, поставьте ему `preempt=2`. Пробный запуск никого не прерывает. Для обычных задач настройку стоит включать только для срочных и коротких. |

У задачи должен быть хотя бы один шаг. Других настроек нет.

### Запуск голосом

Задача с настройкой `voice` запускается, когда человек произносит одну из её фраз. Устройство слушает микрофон постоянно, но **только в заданные часы** (вкладка «Звук», раздел «Голосовые команды», поле «Слушать команды, часы»); если поле пусто, голосовые команды не принимаются вообще. Там же задаётся **префикс** (имя помощника).

```
task "Поболтать" voice="поболтай со мной|давай [немного] поговорим|=на помощь"
  play system:notification volume=60 for=1s
  chat "Человек сказал: {phrase}. Поддержи разговор" for=5m turns=8 assign=talk alert=sos
  if sos
    play system:alarm volume=70 for=5s
  telegram "Поговорили: {talk}"
```

- **Часы** пишутся как `8..22` (с 8:00 до 22:00, конец не входит), `8:30..22:00`, через полночь `22..6`, круглосуточно `0..24`. Время по часам устройства.
- **Префикс** (имя помощника) добавляется в начало каждой фразы: при префиксе `Кузя` слушается «Кузя, поболтай со мной». Вариантов может быть несколько, через `|`: `Кузя|Кузьма` (слушаются все сочетания). В префиксе допустимы те же шаблоны. Смена имени помощника не требует правки задач. Пустой префикс: фразы слушаются как написаны.
- **Фразы без префикса.** Фраза, начинающаяся с `=` (`=на помощь`), слушается как есть, без префикса: так задают аварийные команды, которые неудобно начинать с имени. Такие фразы чаще срабатывают ложно (телевизор, чужой разговор), поэтому выбирайте их осторожно.
- **Фразы** разделяются знаком `|`. Пишите русскими буквами, числа словами; регистр, знаки препинания и «ё» не важны. Фраза должна быть не короче 4 букв (лучше два-три слова, иначе телевизор и разговоры будут запускать задачу). Слова должны быть в словаре русской модели Vosk: проверить фразу можно на вкладке «Звук» в режиме «свободная речь».
- **Шаблоны.** `(а|б|в)` — обязательный выбор одного варианта, `[а|б]` — необязательная часть (можно не говорить), группы можно вкладывать. Знак `|` внутри скобок разделяет варианты, вне скобок — фразы. Например `скажи сколько [сейчас|у нас] (время|времени)` — это шесть фраз. Шаблон разворачивается в обычный список фраз; одна задача может дать не больше 500 вариантов, лишнее — ошибка при сохранении. Одинаковые варианты сливаются; если фраза совпала у двух задач, сработает первая по списку (в журнал попадёт предупреждение).
- **`{phrase}`.** Что человек сказал после префикса (в виде развёрнутого варианта, без знаков препинания и в нижнем регистре: «поболтай со мной»), доступно в задаче как подстановка `{phrase}`, например в теме `chat`. Разные темы можно перечислить фразами (`расскажи про (погоду|здоровье|внуков)`), а произвольную речь после команды принимает знак `*` (следующий пункт).
- **Свободный хвост `*`.** Знак `*` в конце фразы означает «и дальше что угодно». `voice="*"` — любая речь после имени помощника (префикса): «Кузя, расскажи про картошку»; `voice="расскажи про *"` — после этих слов. Сказанное целиком, вместе с хвостом, попадает в `{phrase}` («расскажи про картошку»), и его можно передать в `chat`:

  ```
  task "Собеседник" voice="*"
    chat "{phrase}" from=user for=5m turns=10 assign=resume ok=ok
  ```
  `from=user` говорит шагу, что текст — слова человека: модель отвечает на них сразу, а не начинает разговор «на тему».
  Как это работает: слушатель по-прежнему знает только начало («кузя» или «кузя расскажи про»), поэтому, услышав его, **дослушивает реплику** (хвост, пока человек не замолчит на секунду) и распознаёт её вторым проходом, моделью свободной речи; звук лежит только в памяти и только на это время. Распознавание хвоста начинается заранее и идёт параллельно с тем, как человек договаривает: как только по промежуточному результату слышно начало команды («кузя»), запускается второй проход, так что после конца фразы остаётся доделать немного. В журнале (DEBUG) видно «после конца речи ждали … мс», «разбор начат заранее» и «скорость разбора ×N реального времени» (меньше 1 — устройство не успевает за речью, задержка заметна). Если на вкладке «Звук» выбран **«Звук отклика»**, он играет, когда человек договорил хвост и идёт разбор (не раньше: иначе звук попал бы в микрофон во время речи); по умолчанию отклика нет. Хвост ограничен настройкой «Длина хвоста» на вкладке «Звук» (2–15 с, по умолчанию 8); если после команды молчат дольше 3 секунд, хвоста нет. Хвост **короче двух слов не считается** (это случайный шум или обрывок): задача не запускается, а в журнале (DEBUG) остаётся запись об этом вместе со словами, которые услышал второй проход, и их временем (по ним видно, почему слова не попали в хвост). Если на вкладке «Звук» задана **«Фраза, если команда не расслышана»** (например «Не расслышала, повторите, пожалуйста»), то после неудачного хвоста устройство её произносит, и человек понимает, что команда не принята; по умолчанию фразы нет. Можно говорить с паузой после имени («Кузя… расскажи про картошку») или на одном дыхании. Правила: `*` пишется только в самом конце фразы; `voice="*"` без начала работает только при заданном префиксе (без него пришлось бы слушать любую речь: такая настройка игнорируется), и `=*` нельзя, а `=расскажи *` можно. Если подходит точная фраза (у этой или другой задачи: «кузя сколько времени»), она важнее «*». Задача стартует примерно через секунду после того, как человек замолчал (это пауза, по которой определяется конец реплики; в разбор из неё уходит только 0,3 с), плюс остаток распознавания (на слабых устройствах вроде Galaxy A3 2017 разбор идёт медленнее речи, и остаток заметен). Имя помощника короткое, а любое слово после него запускает задачу: любой разговор, где его произносят, запустит `chat`, поэтому подберите имя, которое в быту не встречается, и при желании добавьте условие в задачу.
- **Порог громкости** (вкладка «Звук», число 0–50, % полной шкалы микрофона; **0 — слушать всегда**, это значение по умолчанию). Тишину слушатель распознавателю не отдаёт, и на слабых устройствах это заметно снижает нагрузку: звук громче порога включает распознавание, а перед ним и около секунды после него тоже передаётся, чтобы не обрезать слово. Слишком высокий порог пропустит тихую речь. Подбирайте его по показанию «громкость сейчас» на той же вкладке: молчите, посмотрите фон, затем скажите команду с того места, откуда её будете давать; порог ставят выше фона и ниже голоса, например 1–3. На сценарии настройка не влияет.
- **Распознавание** идёт на самом устройстве и узнаёт только фразы из задач (всё остальное игнорируется). Звук не записывается и никуда не передаётся. Команда срабатывает, если слова фразы прозвучали подряд; лишние слова вокруг не мешают.
- **Сигнал о том, что команда услышана**, в задаче пишется самим шагом: например, `play` или `say` первым шагом.
- **Когда команды не принимаются:** вне заданных часов, пока говорит синтезатор (и около секунды после него: иначе устройство услышит само себя), идёт видеозвонок или шаг `ask` или `chat` слушает сам. После этого прослушивание возобновляется само.
- Если задача уже выполняется или стоит в очереди, повторная команда игнорируется (запись в журнале). Задача запущенная голосом ставится в очередь как обычная; чтобы она не ждала, можно добавить `preempt=true` (или число 2–9, если она должна прервать и другие задачи с `preempt=true`).
- В журнале запуск выглядит так: `задача «time» запущена по голосовой команде «скажи сколько времени»`; если услышано больше слов, добавляется `(услышано: «…»)`.
- Если задача, запущенная голосом, закончилась ошибкой или `timeout`, в Telegram уходит сообщение, как и после запуска по расписанию.
- Нужны скачанная модель распознавания и разрешение микрофона (см. [`ask`](#ask)). Постоянное прослушивание нагружает процессор и расходует заряд, поэтому лучше задавать часы, когда оно нужно, и держать устройство на зарядке. Услышанное и срабатывания пишутся в журнал (уровень DEBUG, срабатывание — INFO). Раз в 10 минут в журнал (DEBUG, тег `load`) пишется нагрузка приложения по потокам.

## Расписание cron

Пять полей: `минута час день_месяца месяц день_недели`. Время по часам устройства.

| Элемент | Пример | Значение |
|---|---|---|
| `*` | `* * * * *` | каждое значение |
| число | `30 8 * * *` | 8:30 |
| список | `0 8,12,20 * * *` | в 8:00, 12:00, 20:00 |
| диапазон | `0 9 * * 1-5` | в 9:00 по рабочим дням |
| шаг | `*/15 * * * *`, `0-30/10 * * * *` | каждые 15 минут; в 0, 10, 20, 30 минут |

День недели: 0 или 7 — воскресенье, 1 — понедельник. Поля «день месяца» и «день недели» объединяются по **И** (в отличие от классического cron, где они объединяются по ИЛИ).

## Длительности, диапазоны и списки

**Длительность** — число (секунды) или слово из частей «число + единица»: `ms`, `s`, `m`, `h`, `d`. Части можно склеивать.

| Запись | Значение |
|---|---|
| `30`, `30s` | 30 секунд |
| `500ms`, `0.5` | полсекунды |
| `5m` | 5 минут |
| `1h30m`, `1m30s` | составные |

**Диапазон** `30s..2m` — случайное значение между границами. Выбирается **заново при каждом использовании** (на каждой итерации повтора, на каждой паузе). Границы можно написать в любом порядке.

**Счётчик** (первый аргумент `repeat`) — целое число не меньше 1 или диапазон целых `3..5`.

**Список значений** — в скобках через запятую (`[3s,5s,10s,20s]`). Первое срабатывание берёт первое значение, второе — второе и так далее; после конца списка повторяется **последнее**. Каждый элемент может быть диапазоном. Списки поддерживаются в `repeat every=` и `play pause=`. В остальных местах (`delay`, `watch`, `for`, `fade_in`…) допускается одно значение или диапазон.

## Общие списки

Длинный список (слайды, фоны, фразы, звуки), который нужен нескольким задачам, описывается **один раз** в отдельном файле `lists.txt` (вкладка «Задачи» → «Общие списки») и подставляется в шаги ссылкой `@имя`. Файл не лежит в каталоге задач, поэтому его имя не пересекается с id задач (задача `lists` тоже допустима).

```
# lists.txt
mascots = ["ma_c.gif", "ma_e.gif", "ma_d.gif", "ma_g.gif", "ma_j.gif"]
pastels = [
  "#77dd77", "#7fc7ff", "#afdafc",   # запись может занимать несколько строк
  "#fcd975", "#ffb28b"
]
bye = ["Пока!", "До связи!", "До свидания!"]
```

```
task "Вопрос" voice="*" preempt=2
  slide @mascots fade_in=1 fade_out=1 fit=width bg=@pastels
  chat "{phrase}" from=user turns=1 ok=ok
  say @bye
```

Правила:

- Запись `имя = [значения]`: имя из латинских букв, цифр и `_` (до 40 знаков, не с цифры), значения как в обычных списках шагов (строки в кавычках или слова без пробелов). Нужен хотя бы один элемент и не больше 300. Комментарий начинается с `#`. Вложенные списки не допускаются.
- `@имя` заменяет **весь список** там, где допустим список: `slide @mascots`, `bg=@pastels`, `say @bye`, `play @sounds`, вопросы и повторы `ask`. Внутри квадратных скобок (`[@a, "x"]`) и внутри строки в кавычках ссылка не работает: `"пишите на a@b.ru"` остаётся текстом. За ссылкой идёт пробел или конец строки.
- Подстановка происходит при разборе, поэтому всё остальное (проверка существования слайдов и звуков, выбор случайного элемента при каждом выполнении шага) работает так, будто список записан в шаге.
- Неизвестное имя списка — ошибка при сохранении задачи. При сохранении файла списков проверяются все задачи: список, на который ссылается исправная задача, удалить, переименовать или испортить нельзя. Слайд или звук, названный в общем списке, считается используемым (удалить его нельзя, пока на список ссылается задача).
- Файл входит в резервную копию (`lists.txt` в архиве) и очищается сбросом настроек. При каждом изменении прежний файл сохраняется как `lists.txt.bak`.
- В пробном запуске списки подставляются как обычно.

## Шаги

Шаги выполняются по порядку. Действия: [`say`](#say), [`ask`](#ask), [`chat`](#chat), [`play`](#play), [`slide`](#slide), [`photo`](#photo), [`telegram`](#telegram), [`delay`](#delay), [`watch`](#watch), [`background`](#background), [`stop_background`](#stop_background), [`if`](#if), [`repeat`](#repeat), [`stop`](#stop), [`log`](#log).

У действия нет параметров, кроме перечисленных в его таблице: лишний параметр — ошибка с перечнем допустимых.

### say

Произносит текст системным синтезатором. По умолчанию ждёт окончания речи.

```
say "Доброе утро! Сейчас {time}." volume=80
say "Просыпайся!" wait=false
say "Просыпайся! {pause:1s} Пора вставать. {pause:2s..5s} Сейчас уже {time}!"
say ["Доброе утро!", "Здравствуйте!", "С добрым утром, сейчас {time}."]
```

| Параметр | Описание |
|---|---|
| первый аргумент | Текст в кавычках либо список текстов `["…", "…"]`: из списка при каждом запуске шага выбирается случайный (как список файлов у `play`). Допускает [подстановки](#переменные-и-подстановки). Очень длинный текст режется на части по предложениям. Если речь не закончилась за 5 минут, шаг завершается ошибкой. |
| `volume` | 0..100, громкость для этой фразы. Приоритет: `volume` шага, затем «Громкость по умолчанию» на вкладке «Звук», затем громкость системы как есть. Громкость общая для всех звуков (поток «медиа»): смена громкости влияет и на играющий в фоне сигнал. |
| `wait` | `true` (по умолчанию) — шаг ждёт конца речи. `wait=false` — речь идёт **в фоне**, задача идёт дальше (например, в `watch`). Фоновая речь одна: новая заменяет прежнюю. Синтезатор в устройстве один, поэтому две фразы одновременно не звучат: новая фраза обрывает идущую. Для «сказать через паузу» используйте [`background`](#background). |

**Паузы в речи.** `{pause:5s}` внутри текста — молчание на это время: `{pause:500ms}`, `{pause:5s}`, диапазон `{pause:2s..5s}` (случайная пауза при каждом произнесении), не длиннее 2 минут. Паузу отмеряет приложение, а не синтезатор, поэтому она одинакова у любого движка речи и обрывается при остановке задачи и по `stop_background`. Пауза допустима в начале и в конце текста. Только в `say`: в `telegram`, `log`, `stop` она считается ошибкой.

### ask

Задаёт вопрос голосом и слушает ответ с микрофона. Распознаётся короткий ответ двух видов: «да»/«нет» или число от 0 до 999. Результат кладётся в переменную `assign`.

```
ask "Вы приняли таблетки?" assign=pills
ask "Какое давление? Назовите верхнее число." assign=bp kind=number listen=20s retries=2
ask "Сколько вам лет?" assign=age kind=number again="Не расслышала. Назовите число ещё раз."
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| первый аргумент | — | Вопрос, текст в кавычках или список вопросов (выбирается случайный, как в `say`). Допускает [подстановки](#переменные-и-подстановки) и паузы `{pause:…}`, как в `say`. |
| `assign` | обязателен | Имя переменной для ответа (латинские буквы, цифры, `_`). Число (`kind=number`) или логическое значение (`kind=yesno`: «да» — истина, «нет» — ложь). |
| `kind` | `yesno` | `yesno` — слова «да», «нет» и их близкие («ага», «угу», «конечно», «неа»); `number` — число словами или цифрами, от 0 до 999 («сто двадцать пять»). Распознаются только слова своего вида, остальное отбрасывается. |
| `listen` | `15s` | Сколько ждать ответ после вопроса, от `2s` до `2m`. Слушание заканчивается раньше, как только ответ распознан. |
| `retries` | `1` | Сколько раз переспросить, если ответа нет или он не понят: от 0 до 5. |
| `again` | «Повторите, пожалуйста.» | Что сказать при переспросе: текст в кавычках или список `["Не расслышал!", "Скажи ещё раз"]` (каждый раз выбирается случайная фраза, как у `say`). |
| `volume` | как у `say` | Громкость вопроса. |

Порядок: вопрос → короткая пауза → слушание. Если ответа нет, вопрос повторяется (`again`) до `retries` раз; после этого шаг заканчивается **без ошибки, но переменной нет**: условие с ней ложно (`if bp > 140` — нет), а `if not pills` — истинно. Если важно отличить «не ответили» от «нет», переспросите больше раз или сделайте `telegram` с вопросом к близким. Шаги после `ask` продолжаются как обычно.

Нужно: разрешение микрофона (кнопка Allow microphone в окне настроек на устройстве) и модель распознавания, которая один раз скачивается на вкладке «Звук», раздел «Распознавание речи» (около 45 МБ, нужен интернет; дальше работает без сети). На медленной сети скачивание повторяется до 8 раз и продолжается с места обрыва; можно и загрузить файл `vosk-model-small-ru-0.22.zip` с компьютера кнопкой на той же вкладке. Без разрешения или модели шаг завершается ошибкой с понятным сообщением. Пока в задачах есть шаги `ask`, модель держится в памяти устройства (её загрузка занимает около 7 секунд, поэтому она готовится при старте приложения и после правки задач); без `ask` она выгружается через 5 минут после последней проверки микрофона. Проверить микрофон и модель можно там же. Нельзя внутри `background`. В [пробном запуске](#пробный-запуск) ничего не звучит, а ответ задаётся параметром `assume`, например `assume=bp:150,pills:true`.

### chat

Голосовой разговор с ИИ на заданную тему: устройство говорит, человек отвечает, по очереди, пока разговор не закончится. Общие правила для модели (кто она, как говорить, чего не делать) и языковая модель задаются в веб-интерфейсе: вкладка «Чат» (правила), вкладка «Связь», раздел LLM (провайдер Groq, Gemini или «Другой», адрес API, ключ, модель). Подходит любой сервис с API, совместимым с OpenAI. Первый аргумент шага — **текст темы** в кавычках: о чём заговорить; в нём работают подстановки `{переменная}`, например `{phrase}`. Старый вид с именем темы (`chat walk`) больше не поддерживается: тема пишется прямо в шаге. Проверить правила и тему без голоса можно на вкладке «Чат».

```
task "Поболтать" cron="0 11 * * *"
  watch 30s assign=moved
  if moved
    say "Доброе утро! Давайте немного поболтаем."
    chat "Предложи поболтать о внуках и спроси, как у них дела" for=5m turns=8 assign=talk alert=sos
    if sos
      play system:alarm volume=70 for=5s
    telegram "Поговорили: {talk}"
```

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| первый аргумент | обязателен | Текст темы в кавычках, до 1000 знаков, с подстановками `{переменная}` (в том числе `{phrase}`). Объясняет модели, о чём заговорить. |
| `for` | `5m` | Самая большая длительность разговора, от `30s` до `30m` (допускается диапазон). |
| `turns` | `8` | Сколько реплик ИИ самое большее, от 1 до 30. |
| `assign` | нет | Имя переменной, в которую кладётся краткий пересказ разговора (одно-два предложения для родственника). Пусто, если человек ничего не сказал. Если модель для пересказа недоступна, кладутся слова самого человека. |
| `alert` | нет | Имя переменной `true` или `false`: прозвучала ли тревога (человек жалуется на боль или самочувствие, говорит, что упал, ему страшно, просит о помощи). |
| `from` | `topic` | `topic` — текст шага это тема или задание для ИИ («поговорить о погоде»); `user` — это **слова человека**: они становятся его первой репликой, и ИИ сразу отвечает на них (вопрос получает ответ, а не приветствие). Для `chat "{phrase}" from=user` после голосовой команды с `*`. |
| `ok` | нет | Имя переменной `true` или `false`: отвечала ли модель без сбоев. `false`, если нет связи, ключ или название модели неверны, настройки модели не заполнены или связь пропала посреди разговора (ИИ не сказал ни одной реплики или ответ оборвался). С `ok` устройство **не извиняется вслух** за пропавшую связь: что сказать, решает сама задача. |
| `volume` | как у `say` | Громкость речи, 0..100. |

**Как идёт разговор.** Первую реплику говорит ИИ (тема подсказывает, о чём заговорить), затем устройство слушает человека. Слушание заканчивается, когда человек договорил (пауза около полутора секунд), не дольше 30 секунд на реплику. Пока говорит синтезатор, микрофон выключен: перебить устройство нельзя. Разговор заканчивается, когда: ИИ решил закончить (человек попрощался или не хочет говорить), исчерпаны `turns` или `for` (на последней реплике ИИ отвечает по существу и прощается, **не задавая встречного вопроса**: поэтому при `turns=1` разговор получается одним ответом без «а вы?»), человек промолчал два раза подряд, прозвучала тревога, или связь с моделью пропала. Сбой модели или сети **не считается ошибкой шага**: разговор просто заканчивается (если он уже шёл, устройство извиняется), переменные заполняются тем, что есть. Ошибкой считаются только неготовые настройки: нет ключа, нет модели распознавания речи или микрофон занят звонком. Если задан `ok`, то и «модель не настроена» ошибкой не считается: шаг заканчивается, `ok` равно `false`.

**Как узнать, что модель не ответила.** Задайте `ok` и проверьте его условием. Переменная `assign` для этого не годится: пересказ описывает слова человека, поэтому при `turns=1` (ИИ сказал одну реплику и сразу закончил, человек не говорил) он всегда пуст.

```
task "Погода" voice="какая сегодня погода"
  chat "расскажи про погоду, пошути" turns=1 ok=answered
  if not answered
    say "Сейчас нет связи, спросите позже."
```

**Тревога.** Когда ИИ отмечает тревогу, устройство сразу сообщает об этом: в Telegram уходит сообщение с последними словами человека, запись попадает в журнал уровня WARN, `alert` становится `true`, разговор заканчивается (ИИ перед этим коротко отвечает человеку). Сообщение уходит и когда `alert` не задан. ИИ — не медицинская система: он ошибается в обе стороны.

**Дата, время и погода.** К правилам модель каждый раз получает текущие день недели, дату и время устройства, поэтому на вопрос «какой сегодня день?» она отвечает сама. Если в «Система → Параметры» задан город и период обновления погоды больше нуля, добавляется и краткая погода (сейчас, сегодня, завтра). Погода обновляется в фоне и в момент вопроса не запрашивается; если данных нет или они устарели (старше трёх периодов, но не меньше трёх часов), модели сообщается, что погоды она не знает и выдумывать её не должна.

**Что уходит в сеть.** Речь распознаётся на самом устройстве (модель Vosk, как у `ask`, нужна скачанная модель распознавания). В модель отправляется только **текст** разговора (правила, тема, реплики), звук нет. Запросы идут через прокси «LLM», если он включён на вкладке «Связь».

Нужно: настроенная языковая модель (адрес, ключ, имя модели), разрешение микрофона и модель распознавания (см. [`ask`](#ask)). Нельзя внутри `background`. Во время видеозвонка шаг завершается ошибкой, как и `ask`. В [пробном запуске](#пробный-запуск) разговор не ведётся, а результаты задаются через `assume`, например `assume=talk:Говорили о погоде,sos:true` (текст без запятых и двоеточий).

### play

Проигрывает звук: загруженный файл (вкладка «Звук») или системный сигнал `system:alarm`, `system:notification`, `system:ringtone`.

```
play alarm.mp3 volume=80 fade_in=5s fade_out=2s for=30s
play [a.mp3,b.mp3]
play system:notification loop pause=[3s,5s,10s,20s] for=2m wait=false
```

| Параметр | Описание |
|---|---|
| первый аргумент | Имя файла, системный сигнал или список имён (из списка каждый раз выбирается случайный). Несуществующий файл — ошибка при сохранении. |
| `volume` | 0..100, как у `say`. |
| `fade_in` | Нарастание громкости от нуля, длительность. Отсчитывается от начала. |
| `fade_out` | Затухание, длительность. Заканчивается ровно в момент остановки (по `for`, по концу файла, по `stop_background`). Если файл или `for` короче суммы затуханий, они сжимаются. При ручной остановке затухание не длиннее 3 секунд. |
| `for` | Длительность звучания. Без `loop` — ограничитель сверху: звук не длиннее `for` и не длиннее самого файла. С `loop` — звук играет по кругу ровно `for` (паузы входят в `for`). Без `for` и без `loop` файл играет целиком (если длину определить нельзя, то 30 секунд). |
| `loop` | Флаг. Играть по кругу. В обычном режиме требует `for=…` (иначе звук не остановится); в фоновом (`wait=false`) можно без `for`, тогда его гасит `stop_background` или конец задачи. |
| `pause` | Только вместе с `loop`. Пауза между повторами звука: одно значение, диапазон или [список](#длительности-диапазоны-и-списки) `[3s,5s,10s,20s]`. `fade_in` действует только на первый проигрыш. Пауза после одиночного звука не нужна: используйте шаг `delay 3s`. |
| `wait` | `true` (по умолчанию) — шаг ждёт конца звука. `wait=false` — звук играет **в фоне**, задача идёт дальше (например, в `watch`). Фоновый звук один: новый заменяет прежний. |

Фоновые действия (звук с `wait=false`, речь с `wait=false`, блок [`background`](#background)) гаснут при любом завершении задачи (нормальном, по таймауту, по ошибке, при остановке вручную) и по шагу [`stop_background`](#stop_background). Ошибка воспроизведения в фоне пишется в журнал запуска и задачу не прерывает.

### slide

Показывает картинку (слайд) поверх экрана киоска, например помощника-персонажа. Файлы загружаются на вкладке «Слайды» (jpg, png, gif, webp, svg, в том числе анимированные; до 5 МБ на файл, до 30 МБ всего), лежат в `slides/` и входят в резервную копию.

```
slide hello.svg
slide ["hello.svg","hi.gif"] for=5s fit=contain bg=auto brightness=90 fade_in=1s fade_out=2s tap=hide
slide off
```

| Параметр | Описание |
|---|---|
| первый аргумент | Имя файла, [список](#длительности-диапазоны-и-списки) имён (выбирается случайный), [общий список](#общие-списки) `@имя` или `off` — убрать слайд. У `slide off` параметров нет. Несуществующий файл — ошибка при сохранении. |
| `for` | Через сколько слайд скрывается сам. Шаг **не ждёт**: сценарий идёт дальше. Без `for` слайд висит, пока его не скроют (`slide off`, другой `slide`, конец области видимости, касание при `tap=hide`). |
| `fit` | Как вписать картинку в экран: `full` (по умолчанию, растянуть на весь экран), `contain` (целиком, с полями), `cover` (заполнить с обрезкой), `width` (по ширине), `height` (по высоте), `none` (как есть, по центру). |
| `bg` | Фон за картинкой там, где она не закрывает экран: `auto` (цвет краёв картинки) или цвет в кавычках, например `bg="#d81b60"` (`#` без кавычек начинает комментарий). По умолчанию `auto`. Можно дать **список** цветов, например `bg=["#fc6", "#df6", auto]`, или ссылку на [общий список](#общие-списки) `bg=@pastels`: при каждом показе выбирается случайный. |
| `brightness` | 1..100: яркость экрана, пока слайд показан; при скрытии прежняя яркость возвращается. Не задан — яркость не трогается. |
| `fade_in`, `fade_out` | Плавное появление и исчезание, длительность до 10 секунд, как у `play`. |
| `tap` | `hide` — слайд скрывается касанием. По умолчанию касания слайдом игнорируются. |

Правила:

- Слайд показывается **только если киоск на переднем плане**; иначе шаг пропускается (запись в журнале).
- Слайд один на всё устройство: новый `slide` заменяет прежний.
- **Область видимости.** Слайд, показанный в теле `if`, `repeat` или `background`, скрывается при выходе из этого тела (в `repeat` — в конце каждого прохода; чтобы слайд пережил проход, покажите его до `repeat`). Слайд верхнего уровня скрывается в конце задачи, в том числе при ошибке, таймауте и остановке вручную.
- В пробном запуске слайд не показывается, шаг только пишется в журнал.

### photo

Делает фотографию с фронтальной камеры. Если камера не работает, она включается на время снимка (около секунды на экспозицию), затем выключается.

```
photo
photo assign=photo1 size=1280x720
```

| Параметр | Описание |
|---|---|
| `assign` | Имя переменной (латинские буквы, цифры, `_`), в которую кладётся **путь снимка** (`DCIM/fServ/ГГГГ-ММ-ДД/ЧЧММСС.id.jpg`). Такую переменную можно приложить к сообщению: [`telegram … files=[photo1]`](#telegram). |
| `size` | Размер кадра, например `1280x720`, вместо настройки «Разрешение» вкладки «Камера» (то же значение: размер кадра до поворота). Берётся ближайший размер из поддерживаемых камерой (список на вкладке «Камера»). Если камера выключена, она открывается сразу с этим размером, и общая настройка не меняется. Если камера в этот момент уже работает для другого дела (включена на вкладке «Камера», идёт `watch` другой задачи), её размер не трогается, а снимок только уменьшается до нужного (увеличить нельзя). |

Снимок сохраняется в общую папку `DCIM/fServ/ГГГГ-ММ-ДД/ЧЧММСС.id.jpg` устройства (полный размер кадра с настройки «Разрешение» вкладки «Камера», повёрнутый как в превью, JPEG) и виден в галерее. Android 10 и новее: запись без разрешений. Android 8–9: нужно разрешение на запись, кнопка Allow photo storage в окне настроек устройства; без него шаг завершается ошибкой. Хранится не больше 500 последних снимков. Нельзя внутри `background`; в пробном запуске пропускается (в переменную попадает условный путь).

### stop_background

Останавливает все фоновые действия задачи: звук и речь с `wait=false` и блок `background`. Звук затухает по `fade_out` своего `play` (не дольше 3 секунд). Параметров нет.

```
stop_background
```

Если фоновых действий не было, шаг ничего не делает и пишет это в журнал запуска.

### background

Выполняет вложенные шаги **в фоне**, а основной ход задачи идёт дальше сразу. Так звук, пауза и речь выстраиваются в последовательность, пока `watch` продолжает следить за движением.

```
background
  play system:alarm volume=80 fade_in=5s
  delay 10s
  say "Просыпайся! Пора вставать."
```

Правила:
- Внутри обычные шаги (`say`, `play`, `delay`, `telegram`, `log`, `if`, `repeat`). Нельзя `watch`, `photo`, `stop`, вложенный `background`, `stop_background`: камера и остановка задачи принадлежат основному ходу.
- Параметр `wait` у `say` и `play` внутри блока не нужен и запрещён: блок и так идёт в фоне, а его шаги выполняются по порядку.
- Блок один: новый `background` останавливает предыдущий. Звук внутри блока и фоновый `play`/`say` вне блока живут в своих слотах и друг друга не заменяют.
- Блок читает переменные задачи (`assign`) в момент выполнения своих шагов.
- Ошибка в блоке пишется в журнал запуска и задачу не прерывает. Блок обрывается шагом `stop_background` и при завершении задачи.
- В пробном запуске блок выполняется на месте, без звука и без пауз, чтобы вы увидели его шаги в журнале.

### telegram

Ставит сообщение в очередь отправки в Telegram (токен бота и chat id задаются на вкладке «Связь»).

```
telegram "OK\n{time} движение <b>есть</b>,\n<u>вставала</u>"
telegram "Встал в <b>{time}</b>" files=[photo1]
```

| Параметр | Описание |
|---|---|
| первый аргумент | Текст в кавычках; допускает подстановки. |
| `confirm` | Сколько ждать подтверждения доставки: от `1s` до `2m`, например `confirm=10s`. Шаг дожидается, пока Telegram примет **именно это** сообщение, и идёт дальше сразу после доставки, не дожидаясь конца срока. Без `confirm` шаг только ставит сообщение в очередь и сразу продолжается. |
| `assign` | Имя переменной (латинские буквы, цифры, `_`), в которую кладётся результат ожидания: `true`, если сообщение доставлено вовремя, иначе `false`. Работает только вместе с `confirm`. |
| `files` | Список переменных, в которые `photo assign=…` положил пути снимков. Одно фото уходит как фото с подписью-текстом, от 2 до 10 — альбомом, подпись у первого. Если текст длиннее 1024 знаков (предел подписи в Telegram), он идёт отдельным сообщением после фото. Переменная без снимка пропускается. |

```
telegram "Вызов в {time}" confirm=10s assign=sent
if not sent
  say "Сообщение пока не отправилось, позвони по обычному телефону."
```

**Подтверждение доставки.** Сообщение при этом всё равно идёт через очередь: если за `confirm` оно не ушло (нет связи, Telegram не отвечает, не заданы токен и chat id), шаг не считается ошибкой, переменная становится `false`, а сообщение остаётся в очереди и уйдёт позже, когда связь появится. Ничего не теряется и не дублируется. Очередь строго по порядку: если впереди стоит старое застрявшее сообщение, новое тоже не уйдёт, и результат будет `false`, даже когда связь уже есть. Поэтому текст в ветке «не доставлено» лучше писать как «пока не отправилось», а не «нет связи». Если Telegram не настроен, результат `false` приходит сразу, без ожидания. В [пробном запуске](#пробный-запуск) ничего не отправляется, результат по умолчанию `true`, а другую ветку можно проверить параметром `assume=sent:false`.

Сообщение уходит в формате HTML: можно использовать теги `<b>`, `<i>`, `<u>`, `<s>`, `<code>`, `<pre>`, `<a href="…">`, `<blockquote>` и `<blockquote expandable>` (сворачиваемая цитата), `<tg-spoiler>` и перевод строки `\n`. Остальные теги и одиночные `<`, `>`, `&` экранируются и показываются как текст; при неправильной вложенности тегов экранируется всё сообщение. Подставляемые значения переменных тоже проходят эту проверку. Если связи нет, сообщение ждёт в очереди и уходит позже с припиской `Отправлено в ГГГГ-ММ-ДД ЧЧ:ММ` (время события). В очереди до 200 сообщений, они живут до 24 часов; если Telegram отвергает именно это сообщение (HTTP 400), после трёх попыток оно удаляется (запись в журнале). В очереди хранятся только пути снимков; если снимок к моменту отправки удалён, он пропускается.

### delay

Пауза в шаге (ничего не делает, только ждёт). Первый аргумент — длительность или диапазон.

```
delay 30s
delay 2s..5s
```

(У `say` и `play` параметр `wait` — не пауза, а «ждать ли конца».)

### watch

Включает фронтальную камеру и ждёт движения. Возвращается **сразу при первом обнаруженном движении** или по истечении времени, затем камера выключается. Первый аргумент — сколько наблюдать (длительность или диапазон).

```
watch 30s poll=600ms assign=moved threshold=10 area=1.0 zone=bed
```

| Параметр | Описание |
|---|---|
| первый аргумент | Обязателен: сколько наблюдать. |
| `poll` | Интервал между анализируемыми кадрами. Заменяет значение с вкладки «Камера» только на время шага. Практически от 200 мс (анализ кадра на слабых планшетах занимает ~130 мс). |
| `assign` | Имя переменной (`moved`), в которую пишется результат: `true`, если движение было. Имя из латинских букв, цифр, `_`. Переменная доступна в условиях и подстановках. |
| `threshold` | 1..100, порог изменения яркости ячейки. Заменяет значение с вкладки «Камера» на время шага. |
| `area` | 0.05..100, доля кадра в процентах, которая должна измениться. Заменяет значение с вкладки «Камера» на время шага. |
| `zone` | Имя зоны с вкладки «Камера». Движение вне зоны не учитывается. |

Подробности:
- Параметры `threshold`, `area`, `poll`, не указанные в шаге, берутся с вкладки «Камера» (они общие). Поворот изображения и разрешение кадра всегда берутся оттуда же.
- Перед наблюдением камера прогревается около секунды (автоэкспозиция), после чего эталонный кадр запоминается заново. Поэтому очень короткие окна `watch` работают хуже длинных.
- Между окнами `watch` камера выключена и движение не отслеживается. Для непрерывного наблюдения делайте одно длинное окно или ставьте `watch` последним шагом итерации с временем, почти равным периоду. Звук во время наблюдения — фоновым `play`.
- Если камера не заработала (нет разрешения, занята), шаг завершается ошибкой.

### if

Ветвление. Условие — весь остаток строки после `if`. Шаги «да» идут ниже с отступом, ветка `else` необязательна и пишется на том же уровне, что и `if`, сразу после его шагов.

```
if moved and not ill
  say "Доброе утро"
else
  telegram "Не встал"
```

Условие описано [ниже](#условия). Шаги под `if` обязательны (хотя бы один); пустой `else` не допускается.

### repeat

Повторяет вложенные шаги. Первый аргумент — число повторов.

```
repeat 6 every=5m until=moved
  ...шаги...

repeat 3..5 every=[5m,3m,1m]
  ...шаги...
```

| Параметр | Описание |
|---|---|
| первый аргумент | Обязателен: сколько раз повторять — число или диапазон `3..5` (выбирается один раз на запуск шага). |
| `every` | Период между **началами** итераций: длительность, диапазон или список. Если тело итерации заняло меньше, остаток ждётся; если больше, следующая итерация начинается сразу. Список: первая пауза — первое значение, вторая — второе, дальше последнее. Без `every` итерации идут подряд. После последней итерации ожидания нет. |
| `until` | Условие, которое проверяется **после** каждой итерации; если истинно, повтор заканчивается. Условие из нескольких слов пишется в кавычках: `until="moved and not ill"`. |

### stop

Останавливает всю задачу штатно (статус `ok`, причина записывается в журнал). Причина необязательна, пишется в кавычках, допускает подстановки.

```
stop "не нужно, уже встала"
stop
```

### log

Пишет строку в журнал запуска и в общий журнал (вкладка «Журнал»).

```
log "проверка {time} завершена"
```

## Переменные и подстановки

В текстах шагов `say`, `ask`, `telegram`, `log`, `stop` можно использовать `{имя}`:

| Имя | Значение |
|---|---|
| `{time}` | время `ЧЧ:ММ` |
| `{date}` | дата, например «30 октября» |
| `{weekday}` | день недели («пятница») |
| `{phrase}` | что человек сказал после имени помощника, если задача запущена [голосом](#запуск-голосом) (например «скажи сколько времени»); при другом запуске пусто. В пробном запуске задаётся `assume=phrase:…` |
| `{task}` | название задачи (из заголовка, иначе `id`) |
| любое `assign` у `watch` | результат наблюдения: для логического значения «да» или «нет» |
| любое `assign` у `ask` | ответ: число или «да»/«нет» |
| любое `assign` у `photo` | путь снимка |
| `assign` у `telegram` (с `confirm`) | доставлено ли сообщение: «да» или «нет» |
| `assign` у `chat` | краткий пересказ разговора (текст) |
| `alert` у `chat` | была ли тревога: «да» или «нет» |
| `ok` у `chat` | отвечала ли модель без сбоев: «да» или «нет» |

Подстановка неизвестного имени — ошибка при сохранении. Переменная, которой ещё не присвоено значение, подставляется пустой строкой. Переменные живут в пределах одного запуска задачи. Имена `time`, `date`, `weekday`, `task`, `phrase` заняты.

## Условия

Условие используется в `if` и `repeat until=`. Допустимы:

- переменные (`moved`), `true`, `false`;
- числа и строки в кавычках (`"abc"`, `'abc'`);
- сравнения `==`, `!=`, `<`, `>`, `<=`, `>=` (для чисел; сравнение с неизвестным значением даёт «нет»);
- `not`, `and`, `or` (приоритет: `not`, затем `and`, затем `or`);
- круглые скобки.

Примеры: `moved`, `not moved`, `moved and not late`, `(a or b) and not c`, `bp > 140 or pulse > 100`. Истинными считаются `true`, число не 0 и непустая строка.

Условие может ссылаться только на переменные, которые задача создаёт через `assign`, и на встроенные имена; неизвестное имя — ошибка при сохранении.

## Как выполняются задачи

- Расписание проверяется каждые 10 секунд. Одна и та же минута не запускает задачу дважды.
- Задачи идут **по одной** (камера и звук общие), остальные ждут в очереди; исключение — задачи с [`preempt`](#задача): они встают в очереди раньше и прерывают выполняющуюся задачу с меньшим приоритетом. Если задача ещё выполняется или стоит в очереди, её новый запуск по расписанию пропускается (запись в журнале).
- Ручной запуск (кнопка «Запустить» и API) работает всегда, независимо от `enabled` и `cron`.
- Остановка: кнопка «Остановить» (или `POST /api/tasks/stop`) прерывает текущий шаг: речь замолкает, звук гаснет, камера выключается.
- Запуск бывает по расписанию (`cron`), по голосовой команде (`voice`) и вручную.
- Итог запуска: `ok`, `error` (ошибка шага), `timeout`, `cancelled` (остановлена вручную или прервана задачей с `preempt`), `skipped` (опоздание больше `late_ok`).
- Если запуск **по расписанию** закончился ошибкой или таймаутом, в Telegram уходит сообщение. Ручные и пробные запуски в Telegram не пишут об ошибках.
- Ход выполнения (по шагам, с путями вида `1.do.2`) виден на вкладке «Задачи»; хранятся последние 12 запусков.
- Правка одной задачи в веб-интерфейсе заменяет в файле только её строки: комментарии и порядок остальных задач сохраняются.

## Пробный запуск

«Пробный запуск» проходит по шагам и пишет их в журнал, но не говорит, не играет звуки, не включает камеру, не пишет в Telegram и пропускает паузы (`delay`, `every`). Результат `watch` и ответ `ask` в нём задаются параметром `assume`, например `moved:true,bp:150,pills:false` (фраза запуска голосом для `{phrase}` — `phrase:скажи время`) (по умолчанию «движения нет» и «ответа нет»; для `telegram confirm=… assign=…` по умолчанию «доставлено», проверить другую ветку: `sent:false`). Так можно проверить обе ветки условий. Пробный запуск, как и любой другой, ждёт своей очереди, если сейчас выполняется другая задача.

## Ограничения

- Вложенность шагов не больше 8, шагов в задаче не больше 300.
- Каждый вид фонового действия (звук, речь, блок `background`) в задаче один за раз.
- Нет подключаемых измерительных приборов (тонометр с Bluetooth) и других видов наблюдения, кроме движения. Давление пока спрашивается голосом (`ask`).
- Распознавание речи (`ask`) рассчитано на короткие слова и числа в тихой комнате; шумный фон и далёкий голос ухудшают результат. Одновременно слушается только один вопрос или разговор (`ask`, `chat`), внутри `background` они невозможны. Разговор (`chat`) задерживается на время ответа модели: обычно несколько секунд на реплику, через прокси дольше; свободная речь распознаётся хуже, чем короткие слова.
- Расписание проверяется по времени устройства; нет учёта часовых поясов.
- Системные сигналы (`system:*`) зависят от устройства; если сигнала нет, шаг завершается ошибкой.
- Текст сообщения Telegram длиннее 4000 знаков обрезается.

## Полный пример

Будильник: фоновый сигнал с нарастающими паузами, наблюдение за движением, повтор до подъёма, фото и сообщение в Telegram.

Зона `bed` создана на вкладке «Камера». Файл задачи `tasks/wakeup.txt`:

```
task "Подъём"
  cron="0 9 * * *"
  late_ok=0
  timeout=40m

  repeat 6 until=moved
    play system:alarm loop pause=[3s,5s,10s,20s] fade_in=5s fade_out=2s wait=false
    background
      delay 20s
      say "Просыпайся! Пора вставать."
    watch 4m30s poll=600ms zone=bed assign=moved
    stop_background
  if moved
    say "Доброе утро! Сейчас {time}. Не забудьте измерить давление."
    photo assign=photo1
    telegram "Встала в {time}" files=[photo1]
  else
    telegram "К {time} движения нет, не вставала"
```

Утренний замер давления: вопросы голосом, числа в переменные, реакция по результату. Если верхнее число не названо, задача сообщает об этом и заканчивается; пульс необязателен (непонятый ответ подставится пустым). Файл `tasks/pressure.txt`:

```
task "Давление" cron="0 10 * * *" timeout=15m

  say "Пора измерить давление. {pause:2s} Когда измерите, назовите верхнее число."
  ask "Какое верхнее давление?" assign=sys kind=number listen=30s retries=2
  if not sys
    telegram "{time}: давление не названо"
    stop "нет ответа"
  ask "Нижнее давление?" assign=dia kind=number listen=20s retries=2
  ask "И пульс?" assign=pulse kind=number listen=20s retries=1
  if sys > 150 or dia > 95
    say "Давление высокое. Посидите спокойно, я сообщу близким."
    telegram "<b>Давление {sys}/{dia}</b>, пульс {pulse}: выше нормы"
  else
    say "Спасибо, давление в порядке."
    telegram "Давление {sys}/{dia}, пульс {pulse}"
```
