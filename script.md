# Язык сценариев fServe

Задачи описываются декларативно в JSON и хранятся в `tasks.json` на устройстве. Редактировать их можно в веб-интерфейсе (вкладка «Задачи»): общие настройки формой, каждую задачу отдельным JSON-редактором, весь конфиг одним текстом внизу. Любое сохранение проходит проверку: опечатка в имени поля считается ошибкой, чтобы задача не работала молча не так, как задумано. Перед каждым сохранением предыдущая версия попадает в историю (последние 20).

> Этот файл описывает версию приложения 0.6.6 и обновляется вместе с каждым изменением языка (см. [`CLAUDE.md`](CLAUDE.md)). Если описание и поведение разошлись, считайте ошибкой описание и сообщите об этом.

## Структура конфига

```json
{
  "version": 1,
  "comment": "любой текст, не используется",
  "voice": { },
  "zones": { },
  "tasks": [ ]
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `version` | нет | Только `1`. |
| `voice` | нет | Общие настройки речи. |
| `zones` | нет | Именованные области кадра для детектора движения. |
| `tasks` | нет | Список задач. Пустой конфиг (`{"version": 1, "tasks": []}`) допустим. |
| `comment` | нет | Заметка для человека. Поле `comment` разрешено в корне, в `voice`, в задаче, в шаге, в `watch`, в `repeat` и в зоне. |

Любое другое поле считается ошибкой.

## Общие настройки voice и zones

### voice

```json
"voice": {"volume": 70, "lang": "ru-RU", "voice": "ru-ru-x-abc-local", "rate": 1.0, "pitch": 1.0}
```

| Поле | Значения | Описание |
|---|---|---|
| `volume` | 0..100 | Громкость по умолчанию для `say` и `play`, если у шага нет своей. Это громкость системного потока «медиа» устройства. |
| `lang` | `ru-RU`, `en-US`… | Язык синтезатора. |
| `voice` | имя голоса | Конкретный голос (список есть на вкладке «Звук»). Пусто = голос системы по умолчанию. |
| `rate` | 0.3..3 | Скорость речи, 1 = обычная. |
| `pitch` | 0.3..2 | Тон голоса, 1 = обычный. |

### zones

Зона ограничивает область кадра для детектора движения. Координаты в долях кадра от 0 до 1: `[x1, y1, x2, y2]`, где `x1 < x2`, `y1 < y2`, точка (0, 0) — левый верхний угол.

```json
"zones": {
  "bed":   {"rect": [0.1, 0.2, 0.9, 0.9]},
  "door":  {"rects": [[0, 0, 0.3, 0.5], [0.7, 0, 1, 0.5]]},
  "room":  {"rect": [0, 0, 1, 1], "exclude": [[0, 0, 0.2, 0.2]]}
}
```

| Поле | Описание |
|---|---|
| `rect` | Один прямоугольник. |
| `rects` | Несколько прямоугольников, учитываются все. |
| `exclude` | Прямоугольники, которые вырезаются из зоны. |

Нужно хотя бы одно из полей `rect`, `rects`, `exclude`. Имя зоны: латинские буквы, цифры, `_`. Зона подключается в `watch` полем `"zone"`.

## Задача

```json
{
  "id": "wakeup",
  "title": "Подъём",
  "enabled": true,
  "cron": "0 9 * * *",
  "late_ok": "0",
  "timeout": "60m",
  "steps": [ ]
}
```

| Поле | Обязательно | По умолчанию | Описание |
|---|---|---|---|
| `id` | да | — | Латинские буквы, цифры, `_`, `-`, до 40 знаков. Уникален в конфиге. |
| `title` | нет | = `id` | Название для людей: список задач, журнал, подстановка `{task}`. |
| `enabled` | нет | `true` | `false` выключает запуск по расписанию. Вручную выключенную задачу запустить можно. |
| `cron` | нет | — | Расписание (см. ниже). Без `cron` задача запускается только вручную. |
| `late_ok` | нет | `"0"` | Насколько опоздавший запуск ещё разрешён (длительность). Запуск по расписанию, который не успели начать (устройство было выключено, очередь была занята), выполняется, если опоздание не больше `late_ok` плюс запас в 60 секунд на очередь. Иначе запуск пропускается и это записывается в журнал. По умолчанию опоздавшие запуски всегда пропускаются. Верхний предел окна поиска пропущенного срабатывания — 12 часов. |
| `timeout` | нет | `"60m"` | Максимальная длительность всей задачи. Если не уложилась, задача останавливается со статусом `timeout`. |
| `steps` | да | — | Список шагов. |

Других полей у задачи нет.

## Расписание cron

Пять полей: `минута час день_месяца месяц день_недели`. Время по часам устройства.

| Элемент | Пример | Значение |
|---|---|---|
| `*` | `* * * * *` | каждое значение |
| число | `30 8 * * *` | 8:30 |
| список | `0 8,12,20 * * *` | в 8:00, 12:00, 20:00 |
| диапазон | `0 9 * * 1-5` | в 9:00 по рабочим дням |
| шаг | `*/15 * * * *`, `0-30/10 * * * *` | каждые 15 минут; в 0, 10, 20, 30 минут |

День недели: 0 или 7 — воскресенье, 1 — понедельник. Поля «день месяца» и «день недели» объединяются по **И** (в отличие от классического cron, где они объединяются по ИЛИ).

## Длительности, диапазоны и списки

**Длительность** — число (секунды) или строка из частей «число + единица»: `ms`, `s`, `m`, `h`, `d`. Части можно склеивать.

| Запись | Значение |
|---|---|
| `30`, `"30"`, `"30s"` | 30 секунд |
| `"500ms"`, `0.5` | полсекунды |
| `"5m"` | 5 минут |
| `"1h30m"`, `"1m30s"` | составные |

**Диапазон** `"30s..2m"` — случайное значение между границами. Выбирается **заново при каждом использовании** (на каждой итерации повтора, на каждой паузе). Границы можно написать в любом порядке.

**Счётчик** (`times`) — целое число не меньше 1 или диапазон целых `"3..5"`.

**Список значений** — строка через запятую (`"3s,5s,10s,20s"`) или массив (`["3s", "5s", "10s"]`). Первое срабатывание берёт первое значение, второе — второе и так далее; после конца списка повторяется **последнее**. Каждый элемент может быть диапазоном. Списки поддерживаются в `repeat.every` и `play.pause`. В остальных местах (`wait`, `for`, `fade_in`…) допускается одно значение или диапазон.

## Шаги

Каждый шаг — объект с **одним действием** и, если нужно, его параметрами. Два действия в одном шаге — ошибка (разнесите их). Шаги выполняются по порядку; каждый шаг может содержать `"comment"`.

Действия: [`say`](#say), [`play`](#play), [`stop_sound`](#stop_sound), [`telegram`](#telegram), [`wait`](#wait), [`watch`](#watch), [`if`](#if), [`repeat`](#repeat), [`stop`](#stop), [`log`](#log). Зарезервированы `ask` (вопрос голосом, этап 5) и `chat` (разговор с ИИ, этап 6): пока они отвергаются при сохранении.

### say

Произносит текст системным синтезатором и ждёт окончания речи.

```json
{"say": "Доброе утро! Сейчас {time}.", "volume": 80}
```

| Параметр | Описание |
|---|---|
| `say` | Текст. Допускает [подстановки](#переменные-и-подстановки). Очень длинный текст режется на части по предложениям. Если речь не закончилась за 5 минут, шаг завершается ошибкой. |
| `volume` | 0..100, громкость для этой фразы. Приоритет: `volume` шага, затем `voice.volume`, затем громкость системы как есть. Громкость общая для всех звуков (поток «медиа»): смена громкости влияет и на играющий в фоне сигнал. |

### play

Проигрывает звук: загруженный файл (вкладка «Звук») или системный сигнал `system:alarm`, `system:notification`, `system:ringtone`.

```json
{"play": "alarm.mp3", "volume": 80, "fade_in": "5s", "fade_out": "2s", "for": "30s"}
{"play": ["a.mp3", "b.mp3"]}
{"play": "system:notification", "loop": true, "pause": "3s,5s,10s,20s", "for": "2m", "wait": false}
```

| Параметр | Описание |
|---|---|
| `play` | Имя файла, системный сигнал или список имён (из списка каждый раз выбирается случайный). Несуществующий файл — ошибка при сохранении. |
| `volume` | 0..100, как у `say`. |
| `fade_in` | Нарастание громкости от нуля, длительность. Отсчитывается от начала. |
| `fade_out` | Затухание, длительность. Заканчивается ровно в момент остановки (по `for`, по концу файла, по `stop_sound`). Если файл или `for` короче суммы затуханий, они сжимаются. При ручной остановке затухание не длиннее 3 секунд. |
| `for` | Длительность звучания. Без `loop` — ограничитель сверху: звук не длиннее `for` и не длиннее самого файла. С `loop` — звук играет по кругу ровно `for` (паузы входят в `for`). Без `for` и без `loop` файл играет целиком (если длину определить нельзя, то 30 секунд). |
| `loop` | `true`/`false`, по умолчанию `false`. Играть по кругу. В обычном режиме требует `for` (иначе звук не остановится); в фоновом (`"wait": false`) можно без `for`, тогда его гасит `stop_sound` или конец задачи. |
| `pause` | Только вместе с `loop: true`. Пауза между повторами звука, одно значение, диапазон или [список](#длительности-диапазоны-и-списки): `"3s,5s,10s,20s"`. `fade_in` действует только на первый проигрыш. Пауза после одиночного звука не нужна: используйте шаг `{"wait": "3s"}`. |
| `wait` | `true` (по умолчанию) — шаг ждёт конца звука. `false` — звук играет **в фоне**, задача идёт дальше (например, в `watch`). Это параметр `play`, не путать с действием `wait`. |

Фоновый звук один на задачу: новый `play` с `"wait": false` останавливает предыдущий. Он гаснет при любом завершении задачи (нормальном, по таймауту, по ошибке, при остановке вручную). Ошибка воспроизведения в фоне пишется в журнал запуска и задачу не прерывает.

### stop_sound

Останавливает фоновый звук (запущенный с `"wait": false`) с затуханием по `fade_out` того `play`.

```json
{"stop_sound": true}
```

Значение только `true`. Если фонового звука не было, шаг ничего не делает и пишет это в журнал запуска.

### telegram

Ставит сообщение в очередь отправки в Telegram (токен бота и chat id задаются на вкладке «Связь»).

```json
{"telegram": "Встала в {time}"}
```

Текст допускает подстановки. Сообщение уходит в формате HTML: символы `<`, `>` и `&` в тексте экранируются, поэтому разметку внутри сообщения написать нельзя. Если связи нет, сообщение ждёт в очереди и уходит позже с припиской `Отправлено в ГГГГ-ММ-ДД ЧЧ:ММ` (время события). В очереди до 200 сообщений, они живут до 7 дней.

### wait

Пауза в шаге.

```json
{"wait": "30s"}
{"wait": "2s..5s"}
```

Длительность или диапазон. Работает как действие; у `play` одноимённый `wait` — параметр (см. выше).

### watch

Включает фронтальную камеру и ждёт движения. Возвращается **сразу при первом обнаруженном движении** или по истечении `for`, затем камера выключается.

```json
{"watch": {"motion": true, "for": "30s", "poll": "600ms", "save_as": "moved", "threshold": 10, "area": 1.0, "zone": "bed"}}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `motion` | да | Только `true` (другие виды наблюдения появятся позже). |
| `for` | да | Сколько наблюдать (длительность или диапазон). |
| `poll` | нет | Интервал между анализируемыми кадрами. Заменяет значение с вкладки «Камера» только на время шага. Практически от 200 мс (анализ кадра на слабых планшетах занимает ~130 мс). |
| `save_as` | нет | Имя переменной (`moved`), в которую пишется результат: `true`, если движение было. Имя из латинских букв, цифр, `_`. Переменная доступна в условиях и подстановках. |
| `threshold` | нет | 1..100, порог изменения яркости ячейки. Заменяет значение с вкладки «Камера» на время шага. |
| `area` | нет | 0.05..100, доля кадра в процентах, которая должна измениться. Заменяет значение с вкладки «Камера» на время шага. |
| `zone` | нет | Имя зоны из `zones`. Движение вне зоны не учитывается. |

Подробности:
- Параметры `threshold`, `area`, `poll`, не указанные в шаге, берутся с вкладки «Камера» (они общие). Поворот изображения и разрешение кадра всегда берутся оттуда же.
- Перед наблюдением камера прогревается около секунды (автоэкспозиция), после чего эталонный кадр запоминается заново. Поэтому очень короткие окна `watch` работают хуже длинных.
- Между окнами `watch` камера выключена и движение не отслеживается. Для непрерывного наблюдения делайте одно длинное окно или ставьте `watch` последним шагом итерации с `for`, почти равным периоду. Звук во время наблюдения — фоновым `play`.
- Если камера не заработала (нет разрешения, занята), шаг завершается ошибкой.

### if

Ветвление.

```json
{"if": "moved and not ill", "then": [{"say": "Доброе утро"}], "else": [{"telegram": "Не встала"}]}
```

`then` обязателен, `else` нет. Значения `then`/`else` — списки шагов. Условие описано [ниже](#условия).

### repeat

Повторяет шаги.

```json
{"repeat": {"times": 6, "every": "5m", "until": "moved"}, "do": [ ...шаги... ]}
{"repeat": {"times": "3..5", "every": "5m,3m,1m"}, "do": [ ... ]}
```

Внимание: `do` пишется **рядом** с `repeat`, а не внутри него.

| Поле | Обязательно | Описание |
|---|---|---|
| `times` | да | Сколько раз повторять: число или диапазон `"3..5"` (выбирается один раз на запуск шага). |
| `every` | нет | Период между **началами** итераций: длительность, диапазон или список. Если тело итерации заняло меньше, остаток ждётся; если больше, следующая итерация начинается сразу. Список: первая пауза — первое значение, вторая — второе, дальше последнее. Без `every` итерации идут подряд. После последней итерации ожидания нет. |
| `until` | нет | Условие, которое проверяется **после** каждой итерации; если истинно, повтор заканчивается. |

### stop

Останавливает всю задачу штатно (статус `ok`, причина записывается в журнал).

```json
{"stop": "не нужно, уже встала"}
```

Текст причины необязателен (`""`), допускает подстановки.

### log

Пишет строку в журнал запуска и в общий журнал событий (вкладка «Журнал»).

```json
{"log": "проверка {time} завершена"}
```

## Переменные и подстановки

В текстах шагов `say`, `telegram`, `log`, `stop` можно использовать `{имя}`:

| Имя | Значение |
|---|---|
| `{time}` | время `ЧЧ:ММ` |
| `{date}` | дата, например «30 октября» |
| `{weekday}` | день недели («пятница») |
| `{task}` | название задачи (`title`, иначе `id`) |
| любое `save_as` | результат `watch`: для логического значения «да» или «нет» |

Подстановка неизвестного имени — ошибка при сохранении. Переменная, которой ещё не присвоено значение, подставляется пустой строкой. Переменные живут в пределах одного запуска задачи.

## Условия

Условие — строка, она используется в `if` и `repeat.until`. Допустимы:

- переменные (`moved`), `true`, `false`;
- числа и строки в кавычках (`"abc"`, `'abc'`);
- сравнения `==`, `!=`, `<`, `>`, `<=`, `>=` (для чисел; сравнение с неизвестным значением даёт «нет»);
- `not`, `and`, `or` (приоритет: `not`, затем `and`, затем `or`);
- круглые скобки.

Примеры: `moved`, `not moved`, `moved and not late`, `(a or b) and not c`, `bp > 140 or pulse > 100`. Истинными считаются `true`, число не 0 и непустая строка.

Условие может ссылаться только на переменные, которые задача создаёт через `save_as`, и на встроенные имена; неизвестное имя — ошибка при сохранении.

## Как выполняются задачи

- Расписание проверяется каждые 10 секунд. Одна и та же минута не запускает задачу дважды.
- Задачи идут **по одной** (камера и звук общие), остальные ждут в очереди. Если задача ещё выполняется или стоит в очереди, её новый запуск по расписанию пропускается (запись в журнале).
- Ручной запуск (кнопка «Запустить» и API) работает всегда, независимо от `enabled` и `cron`.
- Остановка: кнопка «Остановить» (или `POST /api/tasks/stop`) прерывает текущий шаг: речь замолкает, звук гаснет, камера выключается.
- Итог запуска: `ok`, `error` (ошибка шага), `timeout`, `cancelled` (остановлена вручную), `skipped` (опоздание больше `late_ok`).
- Если запуск **по расписанию** закончился ошибкой или таймаутом, в Telegram уходит сообщение. Ручные и пробные запуски в Telegram не пишут об ошибках.
- Ход выполнения (по шагам, с путями вида `1.do.2`) виден на вкладке «Задачи»; хранятся последние 12 запусков.

## Пробный запуск

«Пробный запуск» проходит по шагам и пишет их в журнал, но не говорит, не играет звуки, не включает камеру, не пишет в Telegram и пропускает паузы (`wait`, `every`). Результат `watch` в нём задаётся параметром `assume`, например `moved:true` (по умолчанию «движения нет»). Так можно проверить обе ветки условий. Пробный запуск, как и любой другой, ждёт своей очереди, если сейчас выполняется другая задача.

## Ограничения

- Вложенность шагов не больше 8, шагов в задаче не больше 300.
- Фоновый звук один на задачу.
- Пока нет шагов `ask` и `chat`, измерений (тонометр) и других видов наблюдения, кроме движения.
- Расписание проверяется по времени устройства; нет учёта часовых поясов.
- Системные сигналы (`system:*`) зависят от устройства; если сигнала нет, шаг завершается ошибкой.

## Полный пример

Будильник: фоновый сигнал с нарастающими паузами, наблюдение за движением, повтор до подъёма, сообщение в Telegram.

```json
{
  "version": 1,
  "voice": {"volume": 70},
  "zones": {"bed": {"rect": [0.1, 0.2, 0.9, 0.9]}},
  "tasks": [
    {
      "id": "wakeup",
      "title": "Подъём",
      "enabled": true,
      "cron": "0 9 * * *",
      "late_ok": "0",
      "timeout": "40m",
      "steps": [
        {"repeat": {"times": 6, "until": "moved"}, "do": [
          {"play": "system:alarm", "loop": true, "pause": "3s,5s,10s,20s", "fade_in": "5s", "fade_out": "2s", "wait": false},
          {"watch": {"motion": true, "for": "4m30s", "poll": "600ms", "zone": "bed", "save_as": "moved"}},
          {"stop_sound": true}
        ]},
        {"if": "moved",
         "then": [{"say": "Доброе утро! Сейчас {time}. Не забудьте измерить давление."}, {"telegram": "Встала в {time}"}],
         "else": [{"telegram": "К {time} движения нет, не вставала"}]}
      ]
    }
  ]
}
```
