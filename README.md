# fServe

Android-приложение «Няня» для планшета в комнате пожилого человека с ослабленной памятью.
Планшет стоит на постоянной зарядке и Wi-Fi, по расписанию выполняет задачи (напоминания,
будильник, разговор), следит за движением по фронтальной камере и пишет близким в Telegram.

- Пакет: `com.ffps.fserv`
- Название: fServe
- Статус: этап 1 (каркас: киоск, веб-интерфейс, API, логи, перезапуск), проверка на устройстве

> Это помощник, а не система безопасности. Он не заменяет живое общение, звонки и визиты.

## Примеры задач

- **Будильник.** С заданного времени проверять движение; если его нет, подать сигнал и сказать
  «Доброе утро, пора вставать», повторить N раз через M минут. При движении поприветствовать,
  напомнить, что сделать, и написать в Telegram, что встала. Если за T минут движения нет,
  написать об этом.
- **Тонометр.** В заданное время напомнить измерить давление, дождаться движения, напомнить,
  как измерять, попросить назвать результат голосом и отправить его в Telegram.
- **Собеседник.** В заданном диапазоне времени при обнаружении движения предложить поболтать,
  поддержать разговор (LLM либо заготовленные сценарии), отправить краткое сообщение о разговоре.

Список задач будет расти, поэтому задачи описываются декларативно в JSON.

## Принятые решения

**Приложение**
- Работает как домашний экран (HOME) на переднем плане; Android 10+ (minSdk 29), без Google-сервисов
  в критичных частях.
- Экран киоска это HTML-страница в WebView (по умолчанию крупные часы, дата, день недели, фон `#036`).
  Страницу можно заменить файлом в `web/`.
- Нативный экран только для базовых параметров (порт, пароль, адрес). Всё остальное управляется
  из браузера.

**Веб-интерфейс и API**
- Встроенный HTTP-сервер (порт 8080 по умолчанию, меняется в настройках). HTTPS с самоподписанным
  сертификатом добавится вместе со звонком из браузера: микрофон браузера требует безопасного контекста.
- `index.html` по умолчанию лежит в APK; если есть `web/index.html`, отдаётся он.
- Простая авторизация (HTTP Basic, логин `admin`, пароль создаётся при первом запуске и показывается
  на планшете по долгому нажатию в левом верхнем углу экрана). JSON отдаётся с отступами.
- `/health` без авторизации (для мониторинга), `/api/info` с авторизацией.
- Записи идут методом `POST` с телом в UTF-8. Основные адреса: `/api/info`, `/api/settings`, `/api/logs`,
  `/api/journal`, `/api/config` (+ `/history`, `/restore`), `/api/ui` (подмена страниц), `/api/restart-app`,
  `/api/reboot?confirm=1`. Встроенная страница управления всегда доступна по `/default`.
- Конфиг задач редактируется как JSON-текст, с проверкой и историей версий.
- Перезапуск приложения и планшета (при правах Device Owner или root), расписание перезапусков в cron-формате.
- Логи с ротацией по размеру: просмотр, скачивание и очистка из веб-интерфейса.

**Датчики и голос**
- Движение: разность кадров в низком разрешении (CameraX), зоны настраиваются в веб-интерфейсе.
- Голос: локальный синтез (один женский голос), распознавание коротких ответов офлайн (Vosk).
- Детекция человека, WebRTC-звонок и Device Owner откладываются на поздние этапы.

**Связь**
- Telegram напрямую: токен бота и chat id в настройках, очередь сообщений с повторами.
- Прокси SOCKS5 с авторизацией, отдельные профили для Telegram, LLM и обновлений.
- LLM: Gemini (через прокси) и Groq, провайдер, модель и таймаут настраиваются, запасной режим без ИИ.

## Сборка и релизы

APK собирается в GitHub Actions и подписывается постоянным ключом из секретов репозитория
(`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`).

- Релиз: тег `vX.Y.Z` либо коммит в `main` с пометкой `[release vX.Y.Z]` в сообщении. В Releases попадают
  `fServe-X.Y.Z.apk`, `.sha256` и `version.json`. Релизная сборка без секрета ключа завершается ошибкой.
- Обычный коммит в `main` собирает APK только как артефакт запуска (Actions, вкладка запуска, Artifacts).
- `versionCode = major*1000000 + minor*1000 + patch`.

## Этапы

1. Каркас: сборка, HOME-приложение, WebView-киоск, HTTP-сервер, `/health`, логи, перезапуск
2. Telegram, прокси, очередь сообщений, обновления
3. Камера и детекция движения, нагрузочный тест на целевом планшете
4. Движок сценариев, озвучка, будильник
5. Качественный голос, распознавание, тонометр
6. LLM и «Собеседник»
7. Детекция человека, звонок, Device Owner
