# <p align="center"><img src="icons/fserv.svg" width="128" alt="fServe"><br />fServe - Android-приложение «Няня»</p>

Android-приложение «Няня» для устройства в комнате пожилого человека с ослабленной памятью.
Устройство стоит на постоянной зарядке и Wi-Fi, по расписанию выполняет задачи (напоминания,
будильник, разговор), следит за движением по фронтальной камере и пишет близким в Telegram.

- Пакет: `com.ffps.fserv`
- Название: fServe
- Статус: версия 1.0.0 (киоск, веб-интерфейс, язык задач, камера и движение, голос, слайды, видеозвонок, Telegram); разговор с ИИ (`chat`: любой сервис с API, совместимым с OpenAI, свободная речь, тревога)

> Это помощник, а не система безопасности. Он не заменяет живое общение, звонки и визиты.

## Примеры задач

- **Будильник.** С заданного времени проверять движение; если его нет, подать сигнал и сказать
  «Доброе утро, пора вставать», повторить N раз через M минут. При движении поприветствовать,
  напомнить, что сделать, и написать в Telegram, что встала. Если за T минут движения нет,
  написать об этом.
- **Тонометр.** В заданное время напомнить измерить давление, дождаться движения, напомнить,
  как измерять, попросить назвать результат голосом и отправить его в Telegram.
- **Собеседник.** В заданном диапазоне времени при обнаружении движения предложить поболтать,
  поддержать разговор (LLM либо заготовленные сценарии), отправить краткое сообщение о разговоре.

Список задач будет расти, поэтому задачи описываются коротким текстом с отступами (по файлу на задачу: `tasks/<id>.txt`, голос и зоны детектора — в настройках приложения). Полное описание языка сценариев: [script.md](script.md).

## Принятые решения

**Приложение**
- Работает как домашний экран (HOME) на переднем плане; Android 8.0+ (minSdk 26), без Google-сервисов
  в критичных частях.
- Экран киоска это HTML-страница в WebView (по умолчанию крупные часы, дата, день недели, фон `#036`).
  Страницу можно заменить файлом в `web/`.
- Нативный экран (иконка приложения) только для базовых параметров: строка состояния службы
  (`Stopped` / `Running: http://адрес:порт` / `Fail: причина`), порт, пароль веб-интерфейса, автозапуск
  при включении устройства, кнопка START/STOP SERVICE. Пароль вводится вручную, сам не создаётся; пока он
  не задан, окно настроек открывается само. Всё остальное управляется из браузера.
- Пока служба работает, в панели уведомлений висит `Running: http://адрес:порт`; нажатие открывает настройки.
  Из киоска настройки открываются долгим нажатием в левом верхнем углу.
- Приложение можно использовать и без роли домашнего экрана: служба запускается кнопкой или автозапуском,
  киоск открывается кнопкой Open kiosk.

**Веб-интерфейс и API**
- Встроенный HTTP-сервер (порт 8080 по умолчанию, меняется в настройках) и рядом HTTPS (порт 8443) с самоподписанным
  сертификатом на адреса устройства (создаётся при первом запуске, хранится в `https.p12`, перевыпускается при новом адресе):
  камера и микрофон браузера нужны для звонка, а доступны только на защищённых страницах. Браузер один раз предупредит о сертификате.
- `index.html` по умолчанию лежит в APK; если есть `web/index.html`, отдаётся он.
- Вход по форме `/login`: запрашивается только пароль (имя всегда `admin`). После входа выдаётся cookie-сессия на год
  (хранится на устройстве, переживает перезапуск; смена пароля и восстановление из копии сбрасывают все сессии);
  кнопка выхода справа в заголовке админки. Пароль задаётся в окне настроек на устройстве. Для скриптов остаётся
  HTTP Basic (`admin:пароль`) без запроса пароля браузером. JSON отдаётся с отступами.
- `/health` без авторизации (для мониторинга), `/api/` с авторизацией (без входа API отвечает 401, страницы ведут на форму входа).
- Записи идут методом `POST` с телом в UTF-8. Основные адреса: `/api/info`, `/api/settings`, `/api/logs`,
  `/api/tasks/list`, `/api/tasks/save`, `/api/tasks/history`, `/api/tasks/restore`, `/api/pages` (подмена страниц), `/api/restart`,
  `/api/reboot?confirm=1`. Встроенная страница управления всегда доступна по `/default`.
- Задачи редактируются как текст (по одной или весь файл), с проверкой, номерами строк в ошибках и историей версий.
- Перезапуск приложения и устройства (при правах Device Owner или root), расписание перезапусков в cron-формате.
- Логи с ротацией по размеру: просмотр, скачивание и очистка из веб-интерфейса.

**Датчики и голос**
- Движение: разность кадров в низком разрешении (CameraX), зоны настраиваются в веб-интерфейсе.
- Голос: системный синтезатор речи Android, распознавание коротких ответов офлайн (Vosk).
- Детекция человека и Device Owner откладываются на поздние этапы.

**Связь**
- Telegram напрямую: токен бота и chat id в настройках, очередь сообщений с повторами (до 200 сообщений, живут 24 часа, при HTTP 400 не более трёх попыток).
- Прокси SOCKS5 с авторизацией, отдельные профили для Telegram, LLM и обновлений.
- LLM: один клиент для любого API, совместимого с OpenAI (пресеты Groq, Gemini и «Другой»), адрес, ключ, модель и таймаут настраиваются.
- Запуск задач голосом: настройка `voice="фраза|фраза"` в задаче и часы прослушивания на вкладке «Звук»; распознаются только эти фразы (Vosk, на устройстве).
- Погода (Open-Meteo, без ключа): город и период обновления в «Система → Параметры», строка на киоске, краткая погода и дата в подсказке чата.

## Сборка и релизы

APK собирается в GitHub Actions и подписывается постоянным ключом из секретов репозитория
(`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`).

- Релиз: тег `vX.Y.Z` либо коммит в `main` с пометкой `[release vX.Y.Z]` в сообщении. В Releases попадают
  `fServe-X.Y.Z.apk`, `.sha256` и `version.json`. Релизная сборка без секрета ключа завершается ошибкой.
- Обычный коммит в `main` собирает APK только как артефакт запуска (Actions, вкладка запуска, Artifacts).
- `versionCode = major*1000000 + minor*1000 + patch`.

## Этапы

1. Каркас: сборка, HOME-приложение, WebView-киоск, HTTP-сервер, `/health`, логи, перезапуск
2. Telegram, прокси, очередь сообщений, обновления
3. Камера и детекция движения, нагрузочный тест на целевом устройстве
4. Движок сценариев, озвучка, будильник
5. Качественный голос, распознавание, тонометр
6. LLM и «Собеседник»
7. Детекция человека, звонок, Device Owner

## Лицензия
Код написан Claude (Anthropic) free. Лицензия: свободное использование.

**Звонок**
- Вкладка «Звонок» (по https://адрес:8443/#call): видеосвязь админка → устройство по WebRTC, точка-точка в локальной сети, без подтверждения
  на устройстве. На устройстве видео собеседника на весь экран и своё в правом нижнем углу (окно поверх киоска, страница `call.html`).
- Звонок только при киоске на переднем плане (экран при необходимости включается). На время звонка камера и микрофон принадлежат звонку:
  `watch`, `photo`, `ask` получают ошибку. Звонок с другого адреса прерывает идущий только с подтверждением; в лог пишутся оба адреса.
  Если страница админки закрыта или пропала сеть (нет ping 12 с), либо киоск ушёл с переднего плана, звонок завершается сам.
- Кнопка колокольчика (только во время звонка) запускает задачу `ring` (если есть и включена). Параметры: разрешение камеры звонящего и камеры устройства.
- Кнопка звонка на киоске (внизу по центру) видна, если есть включённая задача `call`, и запускает её; пока задача идёт, нажатия игнорируются.
- `/phone` (по https://адрес:8443/phone): та же страница админки в режиме «только видеотелефон» на весь экран для закладки
  на смартфоне; экран телефона во время звонка не гаснет. Вкладка «Звонок» в админке работает как раньше.
- API: `/api/call|offer|ping|end|ring`.

**Вкладка «Чат» и проверка модели**
- Вкладка «Связь», раздел «Языковая модель»: пресет Groq, Gemini или «Другой» (любой сервис с API, совместимым с OpenAI: `/chat/completions` и `/models`).
  Пресет подставляет адрес и модель; адрес, ключ и модель запоминаются отдельно для каждого пресета. Список моделей запрашивается кнопкой, в поле «Модель»
  при нажатии виден весь список. Запросы идут через прокси «LLM» (для Groq, Gemini и «Другого» общий флаг), если он включён. В модель уходит только текст разговора.
  Для моделей gpt-oss просятся короткие «размышления» (`reasoning_effort: low`); параметры, которые сервис отклоняет, отправляются повторно без них.
- Вкладка «Чат»: общие правила для модели (пусто = встроенные) и проверка разговора по тексту с произвольной темой, без голоса. Тема разговора пишется прямо в шаге `chat` текстом. Модель отвечает объектом {реплика, тревога, конец}: при тревоге (боль, падение, просьба о помощи) разговор можно прервать и сообщить близким.
- Вкладка «Звук»: проверка микрофона в режиме свободной речи (диктовка Vosk с концом фразы по паузе).
- API: `/api/llm/test`, `/api/llm/models?preset=…`, `/api/chat/test`.

**Запуск задач голосом**
- В задаче: `voice="поболтай со мной|ты здесь"` (можно вместе с `cron`). Вкладка «Звук», раздел «Голосовые команды»: часы прослушивания (`8..22`;
  пусто — не слушать), префикс (имя помощника, можно несколько через `|`) и состояние слушателя. Распознаются только фразы из задач (грамматика Vosk),
  всё остальное игнорируется, звук не записывается.
- Свободный хвост: `voice="*"` (любая речь после имени помощника) или `voice="расскажи про *"`; сказанное целиком в `{phrase}`, хвост распознаётся вторым проходом, не дольше «длины хвоста» (по умолчанию 8 с), короче двух слов не считается.
- Порог громкости (0–50 %, 0 — слушать всегда): тишина распознавателю не отдаётся, нагрузка на слабых устройствах падает; подбирать по строке «Громкость сейчас». У шага `chat` есть `from=user` (текст шага — слова человека, модель отвечает на них сразу) и `ok=имя` — отвечала ли модель без сбоев.
- Шаблоны фраз `(а|б)` и `[а|б]`; фраза с `=` в начале слушается без префикса; сказанное доступно в задаче как `{phrase}`.
- Слушатель уступает микрофон шагам `ask`/`chat` и звонку, а пока говорит синтезатор, не слушает.
- API: состояние слушателя в ответе `/api/stt` (поле `listen`).
- Раз в 10 минут в журнал (DEBUG, тег `load`) пишется нагрузка: процессор приложения в процентах одного ядра, доля времени слушания, память и самые нагруженные потоки.

**Погода**
- «Система → Параметры»: поле «Город» (название или «широта, долгота»; кнопка «Найти город» показывает, что нашлось) и «Обновлять погоду, минут»
  (60 по умолчанию, 0 — погода выключена: не запрашивается, не показывается на киоске и не попадает в чат).
- Open-Meteo: обновление в фоне при запуске, при смене настроек и по периоду; последние данные хранятся на устройстве, устаревшие не показываются.
  Запросы идут через прокси «Погода», если он включён (вкладка «Связь», можно проверить кнопкой).
- Киоск показывает над часами строку вида «☁️ +3°, пасмурно, небольшой дождь», страница получает её из `/api/weather` (с самого устройства доступен без входа).

**Разговор с ИИ (шаг `chat`)**
- Шаг `chat "тема" for=… turns=… assign=… alert=…`: устройство и человек говорят по очереди, пока разговор не закончится (прощание, `turns`, `for`,
  два молчания, тревога, сбой связи). Правила для модели задаются на вкладке «Чат», тема в самом шаге (с подстановками), провайдер, адрес, ключ и модель на вкладке «Связь». В подсказку модели автоматически добавляются дата, время и краткая погода.
- Речь распознаётся на устройстве (Vosk, свободная речь), в модель уходит только текст. Тревожные слова (боль, упал, страшно, помогите) модель
  помечает сама: устройство сразу пишет в Telegram, `alert` становится `true`. Сбой модели или сети разговор обрывает без ошибки задачи.
- Полное описание в `script.md`, раздел `chat`.

**Голос**
- Движок речи после простоя (около 15 минут) выгружается системой, и первая фраза начиналась с паузой в несколько секунд.
  Пока есть включённые задачи с `say` или `ask`, приложение раз в несколько минут (после 8 минут простоя) беззвучно синтезирует
  короткую фразу в файл, а при запуске такой задачи прогревает синтезатор в фоне. Время подготовки и задержки до начала звука пишется в лог (DEBUG).

**Распознавание речи (этап 5)**
- Шаг `ask`: вопрос голосом и ответ «да/нет» или число до 999 с микрофона, офлайн (Vosk, малая русская модель). Модель около 45 МБ скачивается один раз на вкладке «Звук» (раздел «Распознавание речи»), там же проверка микрофона. Микрофону нужно разрешение (кнопка Allow microphone в окне настроек). Описание шага: [script.md](script.md).
- API: `/api/stt`, `/api/stt/download|delete|test|stop`.

**Камера (этап 3)**
- Передняя камера через Camera2, кадры 640x480 с частотой около 10 к/с (самый экономный диапазон), анализируется только яркость. Кадр делится на сетку 64x48, из ячеек вычитается средняя яркость кадра (автоэкспозиция не даёт ложного движения), затем сравнение с предыдущим обработанным кадром. Оценка движения: доля изменившихся ячеек, в процентах. Параметры: интервал, порог ячейки, площадь, поворот, разрешение.
- Камеру открывает служба как foreground-служба с типом camera (нужно разрешение Allow camera в окне настроек). После перезагрузки Android 14+ не даёт запускать камеру из фона, поэтому приложение должно быть домашним экраном: тогда киоск открывается сам и обновляет службу.
- Вкладка «Камера»: живой кадр с закрашенными областями движения, график оценки, параметры, стресс-тест (непрерывный и циклы открытия), итог пишется в журнал.
- API: `/api/camera`, `/api/camera/start|stop|snapshot|history|test`.
